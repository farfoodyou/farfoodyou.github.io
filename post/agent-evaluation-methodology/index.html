Agent 测评：别信单次分数，先算方差和账单

2025 年下半年开始，模型发布会的重心从 AIME 换成了 SWE-bench、Terminal-Bench、BrowseComp、OSWorld。但绝大多数团队照着榜单选完模型，上手后会发现“没那么神”。

问题不在模型，在测评方法。

agent 分数是四元函数

score = f(模型, harness, 工具, 环境)
  • harness：怎么组织循环、怎么管理上下文、失败怎么重试；
  • 工具：bash 沙箱质量、文件编辑器的原子性、浏览器驱动的稳定性；
  • 环境：依赖版本、网络可达性、初始仓库状态。

一个具体例子：SWE-bench 上同一模型，Anthropic 报告 63.7%（无 scaffold）与 70.3%（自建 scaffold，n=489 子集），差 6.6 分，而同代模型之间的差距常常只有 3～5 分。换句话说，scaffold 的差异可以覆盖模型代际差异。

所以看榜单的第一件事是找 harness 描述。找不到，这个数字就当没有。

pass@k 与 pass^k：两个方向相反的指标

指标 含义 适用
pass@kk 次里有一次成功就算成功可以人工挑选结果（如代码建议）
pass^kk 次全部成功才算成功必须无人值守（如 CI 自动修复）

两者的差距随任务步数指数放大。假设单步成功率 0.98，走 30 步：

pass^1 = 0.98^30 ≈ 55%
pass^30（任一次全通）会显著更高，但那不代表可靠

agent 场景要报 pass^k，尤其 k=1 的裸成功率。 但也别走极端：pass^8 的评测成本是单次的 8 倍，得配合分层抽样。

方差：为什么 10 次不够

Anthropic 在 Sonnet 4.5 报 SWE-bench 用 10 次平均，Haiku 4.5 用 50 次平均（公告）。这不是随手写的：

  • 小模型方差大，需要更多样本把标准误压下来；
  • agent 任务的单次结果受环境非确定性影响（时序、网络、临时文件），比单轮问答波动更大。

一个粗略的置信区间公式（二项分布，正态近似）：

SE = sqrt(p(1-p)/n)
500 题、p=0.77  → SE ≈ 1.9%，95% CI ≈ ±3.7%
50  题、p=0.77  → SE ≈ 6.0%，95% CI ≈ ±11.7%

只有 50 题的基准，2 分的差距在统计上毫无意义。 这就是为什么很多“我们领先 X 分”的说法经不起推敲。

成本必须进报表

指标 说明
每任务 token输入/输出/思考分别记
每任务工具调用次数决定沙箱成本
每任务墙钟时间决定并发需求
每任务 $上面三项乘单价
成功率与上面几项并列才有意义

只报成功率不报成本，等于只报射程不报弹药消耗。真实采购决策是“每成功完成一个任务的成本”，这个指标能把“最强模型 + 最差 harness”筛掉。

长任务：看曲线，不看一个点

把任务按步数分桶（1～5、6～20、21～50、50+），分别报成功率，会看到很不一样的形状：

步数桶 模型 A 模型 B
1～595%97%
6～2082%88%
21～5054%71%
50+21%48%

单看总分 A 可能只低 5 分，但在“50 步以上”这一桶差了一倍。你的业务落在哪个桶，决定你该选谁——这一步比总分重要得多。

跑一次 500 题的 SWE-bench，成本结构大概是这样：

项目 量级 说明
每题步数10～50 步每步一次模型调用
每题 token10K～200K含上下文重复读取
总调用数5K～25K 次单模型单次评测
沙箱500 个容器并行需要配额
KV/前缀复用命中率 30%～70%同仓库任务可复用

三件事必须做对：

  1. 容器快照固定：镜像 digest 锁定，否则“同样的题”跑出不同结果；
  2. 网络策略固定：允许联网 vs 禁网，分数差 10 分以上（取决于题目）；
  3. 并发与限流分离：评测集群和线上集群隔离，否则评测会把线上 P99 拖炸。

这也是为什么大厂的评测报告越来越长——评测系统的工程量已经接近被测系统本身。

落地清单

给自己的任务集做测评，按这个顺序：

  1. 固定 harness 版本（打 tag），评的是“模型 + 固定 harness”这个整体；
  2. 每题跑 ≥5 次（小模型 ≥20 次），报均值 + 标准差；
  3. 至少报 pass@1、pass^5 两个指标；
  4. 按步数/难度分桶报结果；
  5. 记录每任务的 token、工具调用、墙钟、成本；
  6. 保留 20% 题目做留出集，防止 prompt 过拟合；
  7. 每季度重跑，因为供应商会静默更新路由与权重。

结论，以及我还不敢说的

  • 公开榜单的作用正在从“选型依据”退化为“排除依据”，榜尾的可以直接排除，榜前几名还得自己测。
  • pass^k + 成本曲线会成为 2026 年的采购语言，比“某某基准第一”实用得多。
  • 评测 harness 会像 CI 一样成为基础设施，需要版本化、可复现、可审计。
  • 最容易被忽略的一点：评测集本身会泄漏。题目一旦进了公开仓库，下一代模型就会“见过”，所以要定期换题、留出集。
