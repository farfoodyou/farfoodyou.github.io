把 Agent 关进笼子：禁网、只读、超时、审计

02:41，采集机一块数据盘水位到 91%，告警进了值班群。

02:44，我把一条「清理过期临时目录」的工单转给执行 Agent。它绑定的服务账号有那台机器的 /data 读写权限，出网无限制，单步超时 30 分钟。这类任务之前跑过十几次，都干净。

02:52，它回了一段三行摘要：删除 12,438 个文件，回收 41 GB，无异常。

03:10，下游对账报缺文件：前一天刚采完、还没入库的原始包，目录名带当天日期，父目录叫 collect_tmp。

定位花了六个小时，因为日志里没有命令

审计那一栏只有三项：工具名 shell、开始时间、退出码，参数没记。我知道它执行过 27 次 shell，不知道执行了什么。

最后从上下文日志里翻出来：该日志为排查模型问题把每轮消息全文落了盘。27 条命令按顺序摆着：它先按 -mtime +3 找过期文件，候选太少，就改成按目录名匹配 *tmp*、*cache*，判据从时间滑到「名字像临时」。第 19 步，它对着 collect_tmp/2024-08-05 执行了 rm -rf。

这一路推断谈不上离谱：工单原文是「清理过期临时目录」，而「临时」没有可执行的定义。换人来做会先问一句这目录能不能删。差别是人问的时候有成本感，Agent 没有：删错了没东西拦，删完也没东西要求它解释。

盘完能力清单，问题很清楚：

能力 事故前的状态 对应的失败模式
网络全部放通，含 DNS 与出站 443可自行下载工具、把读到的内容外传
文件宿主 /data 直接读写挂载误删没有代价，也不需要申请
时间单步 30 分钟，无任务总预算循环删除跑了 8 分钟才被看见
审计只记工具名与退出码事后无法重放，定位只能靠猜

笼子的四根柱子

改法是把「不要做」换成「做不到」。四类约束都在内核或运行时层面生效，不依赖模型配合。

禁网。 每个任务起在独立 network namespace 里，只有 lo，没有默认路由。需要外部数据的任务走显式代理：只允许 GET，域名白名单按任务下发，响应体上限 2 MB，Set-Cookie 剥掉。代理日志进同一审计流，「看过什么」和「做了什么」能对上。

只读。 输入目录一律 MS_RDONLY | MS_NOSUID | MS_NODEV 挂载，唯一可写的是空任务目录，结束打包留证后销毁。路径解析加了 openat2 的 RESOLVE_BENEATH，禁止 .. 与绝对路径逃出任务根。可写目录里只有它自己的产出。

超时。 单次工具调用 90 秒，整个任务 5 分钟，超了杀整个进程树。靠 cgroup v2 的 cgroup.kill 一次干掉组内所有进程，不能只 kill 父进程：Agent 起的子进程经常自己 setsid 跑掉。

审计。 每次调用落一条结构化事件：argv 原样、cwd、stdin 的 sha256、退出码、耗时、产出文件的 sha256。写到另一台机器的只追加日志上，Agent 的 namespace 挂不到那里。

cmd := exec.CommandContext(ctx, "/opt/cage/entry", argv...)
cmd.SysProcAttr = &syscall.SysProcAttr{
    Cloneflags:  syscall.CLONE_NEWNET | syscall.CLONE_NEWNS | syscall.CLONE_NEWUSER,
    UidMappings: []syscall.SysProcIDMap{{ContainerID: 100000, HostID: uid, Size: 1}},
    NoNewPrivs:  true,
}
cmd.Dir = taskRoot
out := io.LimitReader(stdout, 4<<20)  // 输出也有上限

失败安全是设计出来的

改成这套之后，任务成功率从 71% 掉到 58%，掉的全是需要联网自取数据、或要写回共享盘的活。有人提议给「可信任务」开放宽预算的通道，被我否了：只要存在「这种情况可以例外」的分支，模型迟早会构造出那种情况。

三个具体决定：

  • 判断默认拒绝。白名单为空就是没网，不存在「先放通再收紧」。代理连不上就失败退出，不退回直连。
  • 超时不降级。以前超时后把预算翻倍重跑，现在直接失败，中间产物留给人看。翻倍重跑等于把慢变成无限慢。
  • 写操作要审批，界面给 diff 而不是命令串。看 rm -rf /data/collect_tmp/2024-08-05，对比一屏「将删除 12,438 个文件，其中 340 个在最近 48 小时内改动」，判断质量差一档。

重放能力是这次真缺的东西，补得也最重：给定一条事件流，按原 argv 在只读快照上跑一遍，比对产出 hash。同一批工单重放，27 条命令里 3 条因依赖当时网络状态跑不出同样结果，其余 hash 完全一致；定位从六小时压到十几分钟。

后来同类判断错误又出现两次：一次把缓存目录当垃圾清，一次想改系统时区。两次都停在 EPERM 上，任务失败，人收到一条被拒事件。笼子的验收标准是犯错的代价被限制在一个空目录里。
