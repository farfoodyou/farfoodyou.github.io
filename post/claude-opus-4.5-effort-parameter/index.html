Claude Opus 4.5：旗舰降价三分之二，effort 参数成了主角

2025-11-25·6 分钟·2258 字 模型

目录

  1. 旗舰降价背后的三个原因
  2. effort 参数为什么重要
  3. 价格降下来之后，架构会怎么变
  4. 换不换，先问一句
  5. 出处

11 月 24 日，Claude Opus 4.5 发布。最刺眼的不是分数，是价格：

项目 Opus 4 Opus 4.5
输入（$/M）155
输出（$/M）7525
降价幅度—输出与输入都降 67%（1/3 价）

同时带来的还有 effort 参数（发布公告 里客户访谈专门提到它）：默认 high，可以按任务降档，低档位“质量够用但显著更省”。

旗舰降价背后的三个原因

  1. 推理成本下降。稀疏注意力、KV 缓存优化、更便宜的硬件（H200/GB200）叠加，单位 token 成本在 2025 年掉了 5～10 倍。
  2. 小模型挤压。Sonnet 4.5（$3/$15）在多数任务上够用，Haiku 4.5（$1/$5）在编码上到 73.3%。旗舰如果不降价，会被自家产品线架空。
  3. 竞争定价。Gemini 3 Pro、GPT-5 系列都在往下压，“最强”的溢价空间被压缩到“必须一次成功”的场景。

对使用者的直接好处：原本用 Sonnet 的预算，现在可以用 Opus 做规划层，分层 agent 的成本结构进一步下移。

effort 参数为什么重要

官方评测方法写得很细（值得抄）：

所有评测用 64K 思考预算、交错草稿（interleaved scratchpads）、200K 上下文、默认 effort = high、默认采样参数，5 次独立试验取平均。例外：SWE-bench Verified 不用思考预算，Terminal-Bench 用 128K 预算。

三个信号：

  1. 默认 high，说明厂商认为“想得久”是默认正确选择；
  2. effort 可调，说明同一权重下存在“性价比档位”，这是 2025 年最重要的 API 变化（o3-mini 的 reasoning_effort、Qwen3 的 enable_thinking 都是同一思路）；
  3. SWE-bench 不用思考预算，意味着一部分编码能力来自“即时反应”而非长思考——这对延迟敏感的场景是好消息。
resp = client.messages.create(
    model="claude-opus-4-5-20251101",
    max_tokens=16000,
    thinking={"type": "enabled", "budget_tokens": 64000},
    # effort defaults to high; the server decides per task
    messages=[{"role": "user", "content": "refactor this module and make the tests pass"}],
)

Opus 4.5 的强项不在单价或单点分数，在多语言编码：

官方强调的领先项是 SWE-bench Multilingual——“在 8 种编程语言里 7 种领先”，以及 Aider Polyglot、BrowseComp-Plus、Vending-Bench 等偏 agent 的基准。

这个选点很说明问题：

  • 主流基准（Python 单语言）已经饱和；
  • 真实企业的代码库是多语言的（Go + TS + Python + SQL）；
  • 多语言能力靠的是训练数据覆盖面，不是推理长度。

换句话说，编码模型的下一阶段竞争在“广度”而不是“深度”。

价格降下来之后，架构会怎么变

场景 之前 之后
规划层Sonnet 4.5Opus 4.5（$5/$25 可承受）
执行层Haiku 4.5Haiku 4.5 / Sonnet 4.5
批量任务Haiku仍 Haiku
高难度离线Opus 4（$15/$75）Opus 4.5（省 2/3）

典型的“规划贵、执行便宜”结构里，规划层通常只占 token 的 5%～10%。把规划层的价格降 3 倍，整体成本只降 5%～15%，但任务成功率提升可能远超这个比例——这才是降价的真实杠杆。

换不换，先问一句

换之前先回答一个问题：这条链路上失败一次的成本是多少。一次失败要人工返工半小时，规划层就该上 Opus 4.5，执行层继续留 Haiku；一次失败只是重试多花 3 秒，两层都不值得动。

答不上来的团队，先翻失败日志再翻价格表。脚注细到“5 次试验”“默认 effort”这种程度，其实是在提醒同一件事：横评的差别常常不在分数，在定价和口径。
