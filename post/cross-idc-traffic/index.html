跨机房调用为什么慢：条带化与同机房收敛

2020-04-10·6 分钟·2499 字 后端

调度系统上线「条带化」之后，均值几乎没变，p99 从 45ms 涨到 210ms。

条带化指把每个服务的实例均匀撒到所有机房：4 个机房、每服务 32 个实例就是每机房 8 个。理由是单机房故障只损失四分之一容量，而不是整个服务不可用。上线一周后均值平稳，尾部炸了。

先怀疑新加的中间层和 GC，查了两天没结论；把 span 的机房字段打出来才看明白：p99 的请求几乎都至少跨了一次机房，均值被同机房请求稀释，尾部被那一跳决定。

跨机房的概率是乘出来的

纯随机选实例时，单次调用落同机房的概率是 1/4；3 跳全同机房是 0.25 的三次方，1.6%：

最后一行是「同机房优先」生效后的样子（经验值，75% 命中）：跨机房次数 2.25 → 0.75。

跨机房的代价不只是 RTT。实测口径：同城两机房往返 1.5–2ms，跨城 25–40ms；更要紧的是跨机房链路共享，一排队就丢包，而 TCP 丢包后的重传超时是百毫秒量级（RFC 6298 初始 RTO 为 1 秒，实际实现普遍压到 200ms）。210ms 的来源在这里，不是 45ms 加几个毫秒。

尾延迟不是平均值乘以跳数，它是最慢那一跳的重传定时器。

条带化没错，错在没管概率

有人提议把服务整体放进一个机房，就没有跨机房调用。方向是错的：

服务级部署（整体在某机房） 条带化
单机房故障该服务整体不可用1/N 容量
同机房调用天然 100%，依赖拓扑对齐需显式偏好
容量利用率各机房重复部署高

跨机房因此从 0/1 变成比例项，前提是真的去调。

同机房优先，失败再跨机房

改法是把选择顺序固化成有序候选：

  1. 本机房有健康实例 → 只从本机房选；
  2. 本机房没有 → 同城其他机房；
  3. 同城也不可用 → 跨城，并允许降级（放弃次要校验）。

这套顺序在 Envoy 里对应 zone-aware routing 加 priority levels。关键是每级花费不同，预算也不同：

func (c *client) Do(ctx context.Context, req *Request) (*Response, error) {
    deadline, _ := ctx.Deadline()
    for _, tier := range c.tiers(req.Key) { // local → same-city → remote
        left := time.Until(deadline)
        if left < tier.minCost {
            break // 预算连最低成本都不够
        }
        sub, cancel := context.WithTimeout(ctx, tier.budget) // 父预算更短则收窄
        resp, err := c.call(sub, tier, req)
        cancel()
        if err == nil {
            return resp, nil
        }
        if !retryable(err) { // 业务错误换机房也没用
            return nil, err
        }
    }
    return nil, ErrBudgetExhausted
}

两个易错点：

  • 超时之后不要立刻跨机房重试。 本机房超时说明对端慢或过载，跨机房只会更慢，重试还吃掉后面几跳的预算。只有连接层失败（拒绝连接、被重置）才值得换。
  • 预算按跳分配，不平均分。 总预算 200ms、3 跳，我给同机房 40ms、跨机房 60ms、留 40ms 收尾。跨机房跳成本高，更不能给它在本地同样的短超时，否则永远超时、永远白跑。

超时预算怎么被级联放大

最危险的配置：入口超时 200ms，下游每跳都设 500ms。

入口 200ms 就放弃，下游还在跑，占着连接、goroutine 和并发配额直到 500ms。量一高，「没人要的结果」把容量吃干，成功请求也开始超时。

判据只有一条：下游超时必须小于上游剩余预算。实现是把 deadline 一路传下去，而不是每个服务写死超时。

三个反噬

容量倾斜。 同机房优先假设各机房实例数差不多。扩缩容不同步时大机房先满，请求溢到小机房再溢回来；兜底要按目标机房剩余容量加权。

故障瞬间的流量放大。 一个机房挂掉，四分之一流量几秒内摊到另外三个，跨机房流量涨三倍。预留不够就是丢包、重传、再丢包。经验值：跨机房链路按常态峰值的 3 倍预留，或者接受故障时限流。

拓扑信息会错。 注册中心把机房标错，偏好逻辑会把流量锁在错误位置且看起来一切正常。拓扑缺失时退化成全随机而非报错，拓扑与实测 RTT 冲突时以 RTT 为准。
