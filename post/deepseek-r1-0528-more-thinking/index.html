DeepSeek-R1-0528：多想 11K token，涨 17 分

2025-05-29·6 分钟·2244 字 模型

目录

5 月 28 日，DeepSeek 更新了 R1，标签是 0528。模型卡的第一段就给了核心数字：

指标 R1（1 月） R1-0528
AIME 202479.891.4
AIME 202570.087.5
GPQA Diamond71.581.0
LiveCodeBench (2408–2505)63.573.3

而这些提升的来源被写得很直白：思考更长（模型卡）。同一批 AIME 题，旧版平均用 12K token，新版用 23K。

“多想”本身就是一种缩放

这是 2025 年上半年最实在的一条经验：test-time compute 的曲线还在有效区间。

平均思考 12K → 23K   （×1.9）
AIME 2025 70.0 → 87.5 （+17.5）

粗糙地换算：每多 1K 思考 token，AIME 涨约 1.6 分。当然这不是线性关系，越往后边际收益越低，但至少在这个区间还没饱和。

代价同样线性：

  • 输出 token 翻倍 → 成本翻倍（R1 定价 \$0.55/\$2.19，长思考后单题成本约 \$0.05）；
  • 延迟翻倍 → 交互式产品基本不可用，只能放到异步队列；
  • 上下文压力变大（128K 上限里，思考占掉大半）。

所以“多想”不是免费的进步，而是用钱和延迟换分数。能不能接受，取决于业务形态。

后训练配方变了什么

官方说明是“增加了后训练算力 + 引入算法优化机制”。结合对比结果可以推断几件事：

  1. RL 阶段更长了。思考长度自发增长到 23K，说明训练时的长度惩罚被放松，或者课程学习把长度上限推高了。
  2. 数据配比扩了。LiveCodeBench 涨 9.8 分（63.5→73.3），说明代码类可验证数据占比提升。
  3. 工具调用补上了。模型卡把 Tool 类基准单列，这一版开始正经支持函数调用——1 月的 R1 在这一块基本是空白。

第 3 点很重要：R1 最初是“推理专家”，不是“agent 底座”。0528 让它具备了当 agent 脑子的基本条件。

再往下看，8B 蒸馏追平 235B：真正值得琢磨的是：

同一份模型卡里还有一个小模型：

把 R1-0528 的 CoT 蒸馏到 Qwen3-8B Base，得到 R1-0528-Qwen3-8B，AIME 2024 超过 Qwen3-8B 10 分，追平 Qwen3-235B-thinking。

这句话的分量：

  • 一个 8B dense 模型，在数学上追平 235B MoE（22B 激活）；
  • 单卡可跑，延迟和成本低两个数量级；
  • 说明推理能力的载体是数据，不是参数量——至少在有标准答案的领域是这样。

代价也很清楚：8B 模型的常识、长文、多语言、指令跟随会全面弱于 235B。它是“专项选手”，不能当通用推理底座。

# single-GPU distilled model for batch math / code review
vllm serve deepseek-ai/DeepSeek-R1-0528-Qwen3-8B \
  --max-model-len 65536 --gpu-memory-utilization 0.92

推理模型的选型矩阵

到 5 月底，开源侧的选择已经比较清晰：

需求 选择 理由
批量数学/代码，成本敏感R1-0528-Qwen3-8B单卡、够用
线上通用对话 + 偶尔推理V3-0324 / Qwen3-32B（no-think）延迟低
高难度离线分析R1-0528 / Qwen3-235B（think）分数优先
长文档 + 推理暂无好的开源选择原生长上下文仍是短板

“推理”不再是模型属性，而是一次调用里要不要打开的策略。

最后说三句

  • “更长思考”还能继续涨分，但商业上快到头了。23K token 的思考意味着单次请求几十秒，只有离线/异步场景能吃。
  • 蒸馏依然是性价比之王。8B 追平 235B 这件事，会在下半年被各家反复复制（Qwen、Kimi、GLM 都会出小尺寸推理模型）。
  • R1 系列的天花板是非推理能力，写代码能过测试，但不懂业务上下文；做数学能拿高分，但不会查资料。下一代要解决的是“推理 + 工具 + 记忆”的组合，而不是继续加长 CoT。
  • 对使用者的实际建议：别迷信最大思考长度。把 effort 做成可配置项，按请求难度分档，成本能省 3～5 倍，分数只掉 1～2 分。
