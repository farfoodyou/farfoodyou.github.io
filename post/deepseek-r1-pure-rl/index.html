DeepSeek-R1：纯 RL 把推理能力「逼」出来

1 月 20 日，DeepSeek 放出 R1：MIT 协议、权重全开、技术报告同步公开。当天的讨论几乎都集中在“开源追平 o1”，但报告里真正反常识的是另一件事——

R1-Zero 完全没有 SFT，只做强化学习。

o1 把 CoT 藏起来、把训练细节锁死；R1 给出的结论是：只要奖励可验证，长链推理是能被 RL 自己“长”出来的（报告摘要原话是 “incentivized through pure reinforcement learning”）。

两条路线：Zero 和 R1

R1-Zero 的配方干净得离谱：拿 V3-Base，直接上大规模 RL，奖励只有两种——答案对不对（accuracy）、格式对不对（format，把思考过程放进 thinking 标签）。没有 cold start，没有偏好数据，没有过程奖励模型。这套管线写在 GitHub README 的 Model Summary 里。

跑出来的东西很符合“涌现”这个词的定义：

  • 输出长度自发增长，模型自己学会“多想一会儿”；
  • 出现自我验证（self-verification）和回退重算（reflection）；
  • 报告里那个著名的 “aha moment”：模型在推理中途停下来写“等等，这里应该重新检查”。

代价同样明显：可读性差、中英混杂、动不动陷入重复。所以正式版 R1 走了四段式管线：

阶段 做什么 目的
1cold-start SFT，几千条高质量长 CoT给 RL 一个干净起点，压住语言混杂
2面向推理的 RL（GRPO + 规则奖励）提升数学、代码、STEM 的可验证能力
3拒绝采样 + SFT（约 60 万条推理样本 + 20 万条通用样本）把 RL 学到的能力“固化”回底座，补通用能力
4全场景 RL对齐人类偏好，修有用性/无害性

第 2 阶段和第 4 阶段的奖励不同：前者是规则奖励（可验证），后者混入偏好奖励。这也解释了为什么 R1 能一边做 AIME，一边正常聊天——通用能力是第四阶段补回来的。

GRPO：把 critic 省掉

PPO 需要 value network（critic），在 LLM 上它和 policy 同量级，RL 阶段显存几乎翻倍。GRPO 的做法很朴素：同一个 prompt 采一组回答，用组内 reward 的均值方差做归一化，直接当 advantage。

for each prompt q:
    sample G outputs {o_1 ... o_G} ~ π_old(·|q)
    r_i = reward(q, o_i)                  # 规则奖励，标量
    A_i = (r_i - mean(r)) / std(r)        # 组内归一化，替代 critic
    maximize  Σ_i min( ratio_i * A_i , clip(ratio_i, 1-ε, 1+ε) * A_i )
              - β * KL(π || π_ref)

顺手记下几处：

  • 没有 critic 就没有 value loss 和 GAE，实现复杂度降一档，超参少一半。
  • 组内归一化隐含一个假设：同题的不同回答可比。数学/代码这种“答案可判定”的任务成立；开放式写作不成立，所以开放域还得回到偏好模型或成对比较。
  • 没有神经奖励模型，就绕开了 reward hacking 的经典路径。格式奖励只检查思考过程是否放在指定标签里，几乎无法被过度优化。

报告只给了最终方案，没给 RL 的 token 预算曲线。这意味着“要多少 rollout 才能收敛”这件事，目前仍然靠各家自己试。

数字：追平在哪，落后在哪

README 的评测表（pass@1，温度 0.6 / top-p 0.95，最大生成长度 32K）：

基准 DeepSeek-R1 o1-1217 DeepSeek-V3 o1-mini
AIME 202479.879.239.263.6
MATH-50097.396.490.290.0
Codeforces (Percentile)96.396.658.793.4
SWE-bench Verified49.248.942.041.6
MMLU90.891.888.585.2
GPQA Diamond71.575.759.160.0

读法很清楚：在“可验证”的维度上打平甚至反超，在“知识密集”的维度（GPQA、MMLU）落后。 这个 gap 不是 RL 能补的，得靠底座本身的知识量。换句话说，R1 提升的是“用已有知识推理”的效率，不是“知道得更多”。

价格才是真正的冲击

官方 API 定价：输入 $0.55 / 输出 $2.19 每百万 token，缓存命中 $0.14。o1 同期是 $15 / $60。

长 CoT 把输出 token 数放大 3～10 倍。在 o1 的价格下，“让模型多想一会儿”是奢侈行为；在 R1 的价格下，思考成本可以忽略。这可能比榜单更能改变大家的使用方式——一旦思考变便宜，agent 式的多轮自检才划算。

顺带提一句口径问题：R1 是在 V3-Base 上做后训练得到的，流传的“约 29.4 万美元”只覆盖 RL 阶段，别把它当成训练一个 o1 级模型的总成本。

蒸馏：小模型上做 RL 不如抄作业

R1 放出 6 个蒸馏模型，基于 Qwen2.5 和 Llama-3：

模型 AIME 2024 MATH-500 GPQA Diamond
R1-Distill-Qwen-1.5B28.983.933.8
R1-Distill-Qwen-7B55.592.849.1
R1-Distill-Qwen-14B69.793.959.1
R1-Distill-Qwen-32B72.694.362.1
R1-Distill-Llama-70B70.094.565.2

作者给的结论很直接：在这些规模上，从 R1 蒸馏比在小模型上直接做 RL 更划算（README）。32B 蒸馏已经压过 o1-mini（AIME 63.6）。小模型 RL 的收益曲线太陡，样本效率撑不起来。

落地时踩到的几个坑

  • 温度别乱设。 官方建议 0.5～0.7（推荐 0.6），高了会陷入无限重复，低了会僵化。
  • 它对 prompt 很敏感。 同一节里明确说不建议加 few-shot，示例反而会拉低表现；system prompt 会显著改变输出风格。
  • 别把它当通用对话模型。 R1 的通用能力是第四阶段补的，R1-Zero 只适合研究。
  • 部署先用蒸馏版。 671B/37B 激活需要 H800 级别机器；单机消费卡跑 14B 蒸馏才有意义：
vllm serve deepseek-ai/DeepSeek-R1-Distill-Qwen-32B \
  --tensor-parallel-size 2 --max-model-len 32768 --enforce-eager

算笔账：这些数字在机器上怎么搬

推理不是“算”，是“搬”。把 R1 的 decode 拆开看：

数据 每 token 体积 路径 谁在搬
激活权重37B × 1B(FP8) ≈ 37 GBHBM → SMEMTMA / cp.async
KV cache61 层 × 576B(MLA) ≈ 35 KBHBM → SMEM（随上下文增长）TMA（paged）
MoE all-to-all8 专家 × 7168 × 2B × 58 层 ≈ 6.6 MBGPU ↔ GPU / 节点间NVSHMEM / NCCL / RDMA

算一下就明白瓶颈在哪：H100 的 HBM 带宽 3.35 TB/s，光把 37GB 权重读一遍就要 11 ms，对应单流上限约 90 token/s。而同一张卡的 FP8 算力是 1979 TFLOPS——按 roofline，decode 的算术强度只有 2 FLOP/byte 量级，比机器平衡点低两三百倍。

所以 decode 阶段：

  • 算力几乎闲置，HBM 带宽先打满（这就是“memory-bound”）；
  • 增大 batch 能摊薄权重读取（一次读权重服务 N 条请求），吞吐线性上升，直到 KV cache 占满显存；
  • 128K 上下文的 KV 是 35KB × 128K ≈ 4.4 GB，一条请求就吃掉半张 H100 的显存——长上下文的真实成本是显存，不是算力。

prefill 则相反：每 token 约 2 × 37G = 74 GFLOP，算力先满，是 compute-bound。这就是为什么所有推理框架都把 prefill 和 decode 分开调度，甚至拆到不同机器上（PD 分离）——两者的资源画像完全相反。

跨节点专家并行时，那 6.6 MB/token 的 all-to-all 要走 RDMA。按 400 Gbps（50 GB/s）算，一个 token 的专家通信就要 130 μs，比本地算一遍还慢——MoE 的扩展瓶颈是网络，不是 FLOPs。

几句判断

  1. “纯 RL 涌现推理”仍然是黑箱。 报告没给 RL 预算曲线，也没解释长度为什么自发增长；复现依赖数据和 infra，而这两样都没公开。
  2. 规则奖励的边界就是这条路的边界。 数学、代码、有标准答案的 STEM 能吃满；写作、法律、产品决策吃不到。可验证数据管线的建设成本，是这波被低估最严重的东西。
  3. 门槛从算法挪到了工程。 GRPO 的公式半小时看完，把 128K rollout 的训练-推理流水线跑稳要几个月。
  4. 它把 test-time compute 的叙事拆开了：底座打底 + RL 拉长 CoT + 蒸馏普及。三个环节各自可优化，也各自可被超越。

值得盯的两个问题：32B 以下能不能做到 R1 水平；RL 有没有自己的 scaling law。
