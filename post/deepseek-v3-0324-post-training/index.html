DeepSeek-V3-0324：一次「点版本」更新暴露的方法论

2025-03-26·6 分钟·2302 字 模型

目录

  2. 为什么"点版本"能涨这么多

  4. 版本管理比分数更值钱
  5. 参考与数据

3 月 24 日，DeepSeek 在 Hugging Face 更新了 DeepSeek-V3-0324。名字里只有日期，没有“V3.1”，但模型卡给的三行对比很扎眼：

基准 V3 V3-0324
AIME39.659.4（+19.8）
GPQA59.168.4（+9.3）
LiveCodeBench39.249.2（+10.0）

架构没变、总参数没变（671B MoE / 37B 激活）、协议还是 MIT。涨的全是后训练。

这次更新改了什么

官方没有发技术报告，只有模型卡。从公开信息能确认的是：

  • 权重照旧 MIT，商用无附加条款；
  • 推理与函数调用能力提升，模型卡里专门给了“工具调用/多轮对话”的使用建议；
  • 中文写作风格有可见变化（社区反馈集中在“更少套话”）；
  • 分词器/推理配置未变，vLLM、SGLang 直接换权重即可。

换句话说：数据配方 + RL 阶段 + 拒绝采样策略的调整，带来了 20 分的能力跃升，且不需要用户改任何部署。

为什么“点版本”能涨这么多

要理解这个幅度，得先看基线有多低。V3 是 2024 年 12 月发的通用模型，AIME 39.6 属于“不会做题”。R1 证明了同一底座 + 长 CoT RL 能到 79.8。V3-0324 相当于把 R1 那套后训练的部分收益，回灌到通用模型里——不做“推理模式”，但让模型默认会想。

这条路线的要点：

  1. 可验证数据是燃料。数学、代码、结构化推理，答案可自动校验，能大规模合成与筛选。
  2. 拒绝采样比 RL 便宜。给定强教师（R1 或 V3 自己 + 筛选），采样 → 校验 → SFT 的性价比远高于在线 RL；V3-0324 更像“离线蒸馏 + 精选”的产物。
  3. 通用能力不能被 RL 打坏。只见推理数据的模型会变成“解题机器”，中文写作和多轮对话退化。模型卡强调工具调用与写作，说明数据配比里留了大比例通用样本。

对开源自部署，这三点是实际影响：

  • 换了权重就升级，不用改推理栈：这是开源模型相对闭源 API 的一个隐形优势。闭源升级意味着 prompt 重调、评测重跑、成本重算；开源换个 safetensors 就行（前提是没做激进架构改动）。
  • 量化版本要重做：社区量化（GPTQ/AWQ/FP8）随权重更新失效，得等 24～72 小时。生产环境要有“权重版本锁”的意识。
  • benchmark 不可跨版本比较：V3 和 V3-0324 的 AIME 差 20 分，但这是同一架构，说明同一模型的两次后训练迭代，能力差异可以大于两个不同架构。拿三个月前的评测表做选型，基本等于瞎猜。

和 R1 的关系：不是替代，是分叉

维度 DeepSeek-R1 V3-0324
定位推理专家通用基座
输出风格长 CoT（必须）直接回答（可选展开）
AIME79.859.4
延迟高（长输出）低
适用离线难题、比赛、复杂分析线上对话、工具调用、批量处理

实际部署里这两个按请求路由：默认走 V3-0324，命中难题（多步数学、复杂代码）才升级到 R1。这种“双模型路由”在 2025 年上半年成了开源侧的常见架构。

# cheap difficulty probe first, then pick the model
V3_0324 = dict(model="deepseek-v3-0324", max_tokens=4096)
R1      = dict(model="deepseek-r1",      max_tokens=32768)

def route(prompt: str) -> dict:
    if hard_signals(prompt):     # stack traces, math symbols, multi-constraint asks
        return R1
    return V3_0324

版本管理比分数更值钱

同架构反复打磨比换架构更快见效，代价是版本管理变复杂：生产环境要维护的不是“模型版本”，而是“权重哈希 + 评测快照”这一对。V3 → V3-0324 → V3.1 的间隔是月级，闭源旗舰是季度级，落后一个版本就可能差 10 分以上，而这个差距和模型好坏无关。

反例：上半年见过一个团队把线上主力从 V3 换成 V3-0324，指望开放域写作、多跳问答跟着涨 20 分。实测那几项在 ±1 分内浮动，只有数学和代码明显抬升；最后回滚的原因也不是分数，是新权重的量化版本要等 24～72 小时，灰度窗口正好撞上大促。这种涨分只发生在可验证域，其余场景里它是一次无声的权重替换。
