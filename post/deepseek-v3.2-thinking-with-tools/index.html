DeepSeek-V3.2：从「省算力」到「thinking with tools」

12 月 1 日，DeepSeek 发布 V3.2。模型卡开篇把技术路线总结成三件事：

  1. DeepSeek Sparse Attention（DSA）：长上下文效率；
  2. 可扩展的 RL 框架：把后训练算力继续推高；
  3. 大规模 agentic 任务合成管线：把推理嵌进工具使用。

第三条是这次真正的变化。

thinking with tools：推理与行动不再分两段

之前的混合推理模型（Qwen3、GLM-4.5、V3.1）大多是“先想完再调工具”。V3.2 的 chat template 里多了一个明确的能力：在工具调用之间思考。

{"role": "assistant",
 "content": "Hello, I am DeepSeek.",
 "reasoning_content": "thinking..."}          // 思考与工具调用交错的字段

同时新增了一个 developer 角色，专门给搜索类 agent 用（官方 API 不接受这个角色，只在自托管模板里生效）。

这套设计解决的是 agent 的核心痛点：每次工具返回都要重新理解一遍世界。交错思考让模型能在拿到结果后立刻修正假设，而不是把整个任务重新想一遍。

agentic 数据合成：这是最难的工程

模型卡说他们建了一条“大规模 agentic 任务合成管线”。这类管线的实际形态大概是：

任务生成器  →  环境（容器/浏览器/数据库）  →  轨迹采集  →  验证器  →  训练数据
   ↑                                                        │
   └──────────────  失败样本回流（难例挖掘）  ←──────────────┘

难点不在生成任务，而在验证：

  • 代码任务要能跑测试（SWE-bench 式的可执行验证）；
  • 检索任务要能核对事实（需要可信知识源）；
  • 操作类任务要能检查最终状态（文件、数据库、页面）。

没有验证器，合成出来的就是噪声。这条管线才是真正的护城河，模型结构反而是公开的。

Speciale：高算力变体的信号

模型卡里有一句很硬的话：V3.2 在推理上“与 GPT-5 相当”，而高算力变体 V3.2-Speciale 超过 GPT-5，推理能力“与 Gemini 3.0 Pro 同级”。

这段话的信息量：

  • 开源模型开始用“高算力变体”对标闭源旗舰，而不是只比主干；
  • 意味着同一权重下，“思考预算”可以把能力推到另一个档位；
  • 也意味着成本差距被转移到使用方：Speciale 的单价/延迟会高得多。

这和 o3-pro、Gemini Deep Think 是同一个套路：主干模型负责性价比，高算力变体负责刷榜。

DSA 的延续：结构没变，效率继续优化

从 9 月的 V3.2-Exp 到 12 月的 V3.2，注意力结构是一致的（DSA），变化在后训练与数据。这条路径很值得记：

版本 变化 结果
V3.2-Exp（9 月）引入 DSA，其余对齐质量持平，长文效率提升
V3.2（12 月）加 RL、加 agentic 数据推理/agent 能力提升

结构改动先验证、再叠加能力，这是工程上更稳的节奏。很多团队反着来（同时改结构和数据），出了问题无法归因。

自部署要算的三笔账

  1. 显存：671B 总参数，FP8 约 700GB，8 卡 H200 起；
  2. 长上下文：128K + 思考预算，KV cache 占用要单独规划（DSA 能缓解但不清零）；
  3. 工具沙箱：agentic 能力依赖环境，容器/浏览器/网络隔离的成本容易被漏算。

如果只是想要推理能力，R1-0528 系列仍然更划算；V3.2 的价值在“一个模型同时当推理引擎和 agent 底座”。

数据怎么搬：稀疏注意力省的是哪一段带宽

DSA 的收益要落到“每次生成要读多少字节”上才看得清。假设每层 MLA 的 KV latent 是 576 B/token、共 61 层：

阶段 要读的东西 1M 上下文时的量级
索引器打分全部历史的低维索引表示与 L 成正比（所以索引维度必须压得很小）
选中的 top-k KVk × 576 B × 61 层k=2048 时约 72 MB / token
权重37B × 1B ≈ 37 GB / token与上下文无关

由此能推出三件事：

  1. 单流 decode 仍然是权重主导（37 GB vs 72 MB），所以 DSA 对“短上下文、单请求”几乎没帮助；
  2. 长上下文、大 batch 时 KV 读取才会变成主角——这时 DSA 把 O(L) 压到 O(k)，收益立刻显现；
  3. 索引器自己是新的带宽消耗者：它要对历史做打分，读的是压缩表示，但如果维度没压下来，光算 score 就能读 30 GB+。这解释了为什么索引器的 logit kernel 要单独优化（DeepGEMM）、稀疏注意力 kernel 要单独写（FlashMLA）。

“谁搬”这件事也随之变化：稠密注意力是“按需从 HBM 拉整段 KV”，DSA 变成“先让索引器扫一遍低维表（bandwidth-bound 的小读），再按 top-k 做不规则 gather”。不规则 gather 在 GPU 上很难 coalesce，理论带宽利用率常常只有 40%～60%——这是 DSA 真正的工程难点，也是它必须配专用 kernel 的原因。

我的看法

  • “thinking with tools" 会在 2026 年成为开源 agent 模型的基本要求，，纯推理模型会退居”离线分析“场景。
  • agentic 数据合成管线的门槛高于模型本身，谁能稳定产出带验证的轨迹，谁就能持续迭代。
  • “高算力变体”是新的营销层，主干比性价比，变体比上限，两套话术并行。
  • 对使用者的提醒：别拿 Speciale 的分数给主干定价。这两个东西的账单差好几倍。
