四个数：检测系统的账怎么算

2023-08-15·5 分钟·2079 字 工程

季度评审上被问了三次同一个问题：你们的误报率是多少。第一次有人答 29%，第二次有人答 0.18%，第三次有人答「大概三成吧，但主要是低危」。三个数都不是编的，来自同一套系统，差在分母。

那天之后我把检测链路上所有对外说过的数重新算了一遍。下面四个是本账本里最贵的。

精度 71%

日送检 180 万个文件，产生 1.1 万条告警，人工复核确认 7800 条。精度 = TP / (TP + FP) = 7800 / 11000，71%。

这个数只对「送检全集」成立，而且依赖复核队列不积压：积压时没复核的告警按未确认计，精度会被低估；反过来，如果只统计「复核完成」的那部分，精度会被高估，因为复核员倾向于先处理看起来像真的。我们的做法是把未复核的告警单独列一档，按历史复核确认率折算，不混进分子。

按告警算出来的 29% 误报率，和按文件算的 0.18%（3200 个误报文件 / 180 万），差 160 倍。两个数都对，用途不同：前者衡量复核成本，后者衡量对业务的影响。对外只说一个，必然挨问。

漏报的 0.06% 只是一个上界

漏报没法直接数，只能估。每月从放行流量里分层抽样 5000 个文件做人工复核，连续几个月都是 0 命中。0 命中不等于 0 漏报，按 rule of three，95% 置信上界约等于 3 / n：

p95_upper = 3 / n = 3 / 5000 = 0.0006  →  0.06%

n 要翻到 3 万才能把这个上界压到 0.01%。人工复核 3 万个文件不现实，所以真实做法是分层：按文件类型、来源渠道、评级分十几层，每层抽固定量，再按层权重加权。这样名义上 5000 个样本能覆盖住大部分层，代价是每层的估计都很粗。

这里有个容易忽略的偏差：抽样只覆盖「已送检」和「已放行」两部分，从来没进过检测链路的文件不在分母里。这部分靠采集侧的对账来兜：入口网关上记接收数，检测队列里记入队数，两个数的差就是漏送，按天对，超过 0.1% 就查。

8 分钟的沙箱和 5/s 的吞吐

延迟预算写的是 p99 三十分钟。实际拆下来，p50 只有 40ms（静态扫描），p99 由沙箱排队决定。单个样本在沙箱里平均跑 8 分钟，全集群 2400 个并发槽位（约 60 台、每台 40 个），吞吐约 5 个每秒。高峰送检 900 个每秒，其中约 2% 需要沙箱，也就是 18 个每秒进队列，是吞吐的三倍半。

按 Little 定律 L = λW，即使到达率不变，队列也会一直涨：积压 30 万个、到达 18 个每秒，停留时间 16667 秒，四个半小时。这不是容量规划的问题，是「2% 触发沙箱」这个策略在高峰期不成立。后来把触发条件从「评级中以上全送」改成按家族命中与评级分层，高峰期的沙箱占比压到 0.6%，队列才稳在十分钟以内。

延迟指标本身也有坑。用直方图算 p99 时，桶边界一旦按线性切分，长尾全挤在最后一个桶里，p99 永远等于桶上界。我们改成指数桶，从 10ms 到 1h 共十几档，并且把「排队时间」和「执行时间」分成两个指标：混在一起算，优化了执行时间也看不出效果。

450 条回流样本一个月

申诉每月 900 条左右，成立一半，450 条误报样本进回归集；加上每天从放行流量里随机抽 20 个文件，回归集一个月长一千多条，一年下来会到万级，跑一遍要几个小时。

所以回归集要分层保留：申诉样本永久留，随机抽样只留三个月，重复的按哈希去重。规则包发布前跑全量回归，命中变化超过 0.5% 就阻断，变化在 0.1% 到 0.5% 之间要求人工看一眼差异清单。这个阈值是拍的，作用是拦住「顺手改一条规则结果扫掉一整类」这类事故，不是保证质量。

数据对账还有一个副产品：把「申诉成立」的样本按规则分组统计，前三条规则贡献了四成的误报。这类清单比任何评分模型都更能指导下一轮规则治理。

四个数放在一起

指标 定义式 数据来源 常见错口径
精度TP / (TP + FP)复核结论表只算复核完成的，高估
误报率FP / 全部文件同上与「按告警」混用，差两个数量级
漏报上界3 / 抽样量（95%）分层抽样 + 人工复核把上界当实测值对外说
端到端延迟排队 + 执行，分指标直方图指数桶桶边界线性，p99 被截断

这四个数每个月光是采集和对账就要一个人两天。曾经有人提议把它们做成一个 0 到 100 的健康分，被否掉了：这四个数之间没有稳定的换算关系，合成一个分只会让讨论停在分数上。

现在评审会上先报口径再报数，谁也不许说「大概三成」。
