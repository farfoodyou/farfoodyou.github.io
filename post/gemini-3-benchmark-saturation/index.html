Gemini 3：1501 Elo 之后，评测本身成了问题

11 月 18 日，Gemini 3 发布。官方给的几个数字：

基准 Gemini 3 Pro
LMArena1501 Elo
GPQA Diamond91.9%
Humanity's Last Exam（无工具）37.5%
MathArena Apex23.4%
SWE-bench Verified76.2%
Terminal-Bench 2.0显著超过 2.5 Pro

同期还放出了 Google Antigravity（一个 agentic 开发平台）和 Deep Think 模式（面向 Ultra 订阅者，稍后开放）。

这份成绩单里，最值得讨论的其实是评测已经快测不出差距了。

1501 Elo 意味着什么

LMArena 的 Elo 是成对比较算出来的：两两投票，拟合 Bradley–Terry 模型。问题在于区间压缩：

  • 1200 → 1300 用了几十个模型、两年；
  • 1400 → 1501 只用了几个月。

当一个模型的胜率对同代对手达到 65%～75%，要再提高 5 个百分点，需要的样本量会指数上升。1501 这个数字的可信区间，可能已经覆盖了前三名的差距。

GPQA 91.9% 已经接近天花板

GPQA Diamond 是“博士级科学问答”，448 道四选一。人类专家（同领域 PhD）大约 65%～80%，非专家高学历者约 34%。

91.9% 意味着：

  • 高于该领域人类专家；
  • 剩下的 8% 里，一部分可能是题目本身有歧义/标注错误；
  • 这个基准对前沿模型的区分度基本耗尽。

接下来的科学推理评测会转向“开放性可验证任务”（HLE、MathArena Apex 这类），但它们的样本量小、噪声大，单次分数波动可能有 ±5 分。

SWE-bench 76.2%：编码是唯一还在涨的维度

模型 SWE-bench Verified 时间
Sonnet 472.5%2025-05
Sonnet 4.577.2%2025-09
Gemini 3 Pro76.2%2025-11

可以看到编码分数已经挤在 75%～78% 的窄带里。原因不是模型不行，而是基准的构造方式：SWE-bench 的题目来自真实 PR，很多问题的“正确答案”依赖仓库当时的约定，模型再强也难猜中维护者的偏好。

所以下半年编码评测开始转向：

  • SWE-bench Multilingual（多语言仓库）；
  • Terminal-Bench 2.0（真实终端操作，多步）；
  • 企业自建任务集（最贴近生产）。

多模态才是这次的差异点

官方话术里，Gemini 3 Pro 的“multimodal reasoning”占了很大篇幅（包括视频/屏幕理解、图表推理）。这块没有统一基准，但对 agent 很关键：

  • 操作浏览器的 agent 必须“看懂”渲染结果，而不只是读 DOM；
  • 读录屏排障需要跨帧定位；
  • 图表/表格的数值推理是真实业务里最常见的多模态需求。

从 2025 年下半年开始，“多模态”从“能描述图片”变成了“能在推理链里用视觉信息”，这是能力性质的改变，不是分数提升。

说到最后，给几句自己的判断：

  • 公开榜单正在失去区分度。2026 年的选型会更多依赖自建任务集 + 成本曲线，而不是某个 Arena 分数。
  • “无工具”的口径会变重要。同一个基准，允许搜索/代码执行和不允许，差 10～30 分；发布方不写清就是耍流氓。
  • agent 平台和模型一起发，会成为常态（Antigravity 之于 Gemini，就像 Claude Code 之于 Claude）。模型能力要靠 harness 兑现。
  • 对工程团队：别再等“最强模型”。现在同代模型在生产任务上的差距常常小于 prompt 与 harness 的差距。
