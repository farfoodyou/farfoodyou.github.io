GLM-4.5：把「思考开关」做成开源模型的默认项

2025-07-30·6 分钟·2441 字 模型

7 月 28 日，智谱开源 GLM-4.5 系列：GLM-4.5（355B 总 / 32B 激活）和 GLM-4.5-Air（106B / 12B），Base、混合推理版、FP8 版一起放，MIT 协议（模型卡）。

到 7 月底，“开源 + MIT + 双模式”已经不是差异化了，区别在于它把 agent 工具链一起做了。

双模式怎么切

模型卡给的接口很直接：thinking 模式用于复杂推理和工具调用，non-thinking 用于即时响应；切换靠 chat template 参数。

# after deploying on vLLM / SGLang, thinking is on by default
resp = client.chat.completions.create(
    model="glm-4.5",
    messages=msgs,
    extra_body={"chat_template_kwargs": {"enable_thinking": False}},  # non-thinking
)

这和 Qwen3 的 enable_thinking 几乎一模一样——接口正在趋同，对使用者是好事：同一套路由代码可以对接多家模型。

双模式的实际价值在于成本分层，而不是“能力更强”：

请求类型 模式 典型 token 相对成本
分类、抽取、改写non-thinking200～8001×
代码审查、方案对比thinking3K～15K10×～30×
复杂调试、多步规划thinking（长预算）20K+50×+

一个中等规模的业务，如果能把 70% 的请求留在 non-thinking，账单能砍掉八成。

355B/32B 这个尺寸的用意

型号 总参数 激活 用途
GLM-4.5355B32B主力，双卡以上
GLM-4.5-Air106B12B单机 8 卡以内
GLM-4.5-FP8355B32B显存省一半，吞吐更高

355B/32B 的激活比例约 9%，比 Kimi K2（3.2%）保守，比 Qwen3-235B/22B（9.4%）接近。这是“能力/成本”折中的甜区：单 token 算力约等于 32B dense 模型，但知识容量接近 355B。

官方同时放 FP8 权重，是很实际的一步：BF16 的 355B 需要 ~710GB 显存，FP8 降到 ~355GB，8 卡 H100/H200 就能跑，部署门槛从“机房”降到“一台机器”。

官方定位里的 agent 能力拆开是三层：

模型卡把定位写成 “foundation models designed for intelligent agents”。这个定位拆成三件事：

  1. 工具调用格式稳定：多轮 function call 不乱、不丢参数；
  2. 长任务不跑偏：几十步之后还记着自己的目标；
  3. 失败可恢复：工具报错时能读懂错误信息并换方案。

这三条都没有标准基准，只能靠实际 harness 测（SWE-bench、Terminal-bench、自建任务集）。模型卡给的分数是参考，真实差距在“跑 50 步之后还剩多少成功率”。

开源侧的横向位置（2025-07）

模型 总/激活 上下文 许可证 特点
Kimi K21T / 32B128KModified MIT不做长思考，agent 底座
GLM-4.5355B / 32B128KMIT双模式 + FP8 权重
Qwen3-235B235B / 22B32K（YaRN 131K）Apache 2.0尺寸谱系最全
DeepSeek-V3-0324671B / 37B128KMIT通用基座，推理靠 R1

有意思的是激活参数高度收敛在 22B～37B。这不是巧合：这个区间刚好对应“单 token 算力 < 2 张卡的持续供给能力”，是推理成本曲线上的一个合理落点。

选型时的三个坑

  1. 别只看激活参数。MoE 的显存由总参数决定，355B 即使激活 32B，也得按 355B 备显存；“激活小”不等于“卡少”。
  2. FP8 权重要配对应 kernel。老版本 vLLM/SGLang 可能不支持新的 scale 格式，部署前先确认版本矩阵。
  3. 双模式的评测要分开报。同一个模型 thinking/non-thinking 是两条曲线，混着比没有意义。

同一张卡上的两笔账

8 卡 H200 是 1.13 TB 显存，355B/FP8 的权重占 355 GB，剩下 773 GB 要给 KV、激活和 batch。按 non-thinking 每条输出 500 token、thinking 每条输出 8K 算，同样的显存前者能压的并发是后者的 16 倍。把 70% 请求留在 non-thinking，总成本是全走 thinking 的 34%（(0.7×1 + 0.3×16) / 16）；剩下 30% 的难题仍然拿得到长思考。双模式的全部价值就是这个 34% 与 100% 之间的差价，跟 thinking 档多考几分没关系。
