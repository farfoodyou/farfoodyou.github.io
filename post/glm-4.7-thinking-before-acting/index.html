12 月 22 日，智谱开源 GLM-4.7：355B 总参数 / 32B 激活，MIT 协议。模型卡给的三行对比很清楚：

基准 GLM-4.6 GLM-4.7
SWE-bench Verified68.073.8（+5.8）
SWE-bench Multilingual53.866.7（+12.9）
Terminal-Bench 2.024.541.0（+16.5）

架构没变、参数没变、协议没变。涨的全是 agent 行为。

三个新概念：交错、保留、轮次级

模型卡把这次的能力改进归到三个机制上：

  1. Interleaved Thinking（交错思考）：每次回复、每次工具调用之前都先想一遍；
  2. Preserved Thinking（保留思考）：把之前的思考结果保留到后续轮次，不用每次重建世界观；
  3. Turn-level Thinking（轮次级思考）：按轮次粒度决定“这一轮要不要深想”。

第一条是“想完再动手”，第三条是“决定要不要想”。第二条最容易被忽略，但工程价值最大：它把思考从“一次请求的临时产物”变成了“跨请求的状态”。

对 agent 来说这直接对应一个老问题：

问题 没有保留思考 有保留思考
第 20 步还记得第 3 步的约束吗靠上下文窗口硬塞思考里显式写着
每轮的成本重新推理整段上下文只推理新增部分
上下文溢出风险高低（思考可压缩）

这本质上和 Claude 4 的“模型自己写记忆文件”是同一类解法，只是实现层次不同（一个是 KV/思考状态，一个是文件系统）。

Terminal-Bench 从 24.5 到 41.0 意味着什么

Terminal-Bench 测的是多步终端操作：装依赖、跑构建、改配置、看日志。24.5 → 41.0 是一个很大的跳跃，但离“可靠”还远——41% 意味着每 5 个任务就有 3 个失败。

这类任务的失败模式很固定：

  • 命令拼错、路径写错（低级但高频）；
  • 不理解报错语义，重复同一个错误操作；
  • 环境状态污染（上一步留下的文件影响下一步）；
  • 长任务漂移（做到一半忘了最初目标）。

“思考前置”恰好对第一、二、四点有效：想一遍再敲命令，能过滤掉大部分手滑；解释报错再重试，能避免死循环。

算笔账：32B 激活的账

数据 体积 路径 谁在搬
常驻权重355B × 1B(FP8) ≈ 355 GBHBM 常驻加载时一次
每 token 激活权重32B × 1B ≈ 32 GBHBM → SMEMTMA / cp.async
每 token KVMLA 压缩后约 30～70 KBHBM → SMEMTMA（paged）
MoE all-to-all每层约 8 专家 × hidden × 2BGPU ↔ GPUNVSHMEM / NCCL

在 H200（4.8 TB/s）上，读 32 GB 需要 6.7 ms，单流上限约 150 token/s。而 agent 场景里每次工具调用平均要吐 300～800 token，折算下来单步 2～5 秒——agent 的墙钟时间主要花在 weight streaming 上，不是在“思考”上。

所以“交错思考”的成本要这么算：

每步成本 ≈ 权重读取(6.7ms) × 输出 token 数 + 思考 token 数 × 单 token 成本

思考 token 也是 token，也要过一次权重。“每次动作前都想想”等于把权重读取的次数乘上步数——这是 GLM-4.7 类模型真正的账单，也是为什么“轮次级思考”（不该想的轮次不想）很重要。

到年底，开源第一梯队的编码能力已经进入 70～75% 的窄带，和闭源旗舰（77～81%）只差几个点。差距从“能力”变成“稳定性与成本”。

几句判断

  • “思考状态”会成为 agent 模型的核心竞争力，，它同时解决成本（少重复推理）和一致性（跨轮不漂移）两个问题。
  • 轮次级思考（该想才想）比“一律长思考”更实用，因为它直接决定 agent 的步均成本。
  • MIT 协议 + 32B 激活是当前最优的商业化组合，法务简单、两张卡能跑、能力够用。
  • 对工程团队：先把“思考缓存”做进 harness（把上一轮的思考摘要喂回去），比换更大的模型见效快。
