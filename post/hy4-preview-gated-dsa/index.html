Hy4 preview：770B/49B，把「抄作业」做成了体系

8 月 28 日，腾讯混元开源 Hy4 preview（Apache 2.0）：770B 总参数 / 49B 激活。

它的结构说明里几乎点名了一半同行——“inspired by DeepSeek and GLM"——这在 2026 年是坦诚而高效的工程态度：结构上的最佳实践已经收敛，没必要重新发明。

结构清单

组件 配置 来源/动机
主干78 层：第 1 层 dense FFN + 77 层 MoE首层 dense 保稳定
专家每层 256 路由 + 1 共享，top-8 激活细粒度专家（DeepSeek 路线）
注意力Gated DSA（门控稀疏注意力）DeepSeek 稀疏注意力 + 门控
索引复用IndexCache（跨层复用索引）同 GLM IndexShare
残差iHC（identity Hyper-Connections）加强跨层信息流
投机解码内置 1 个 MTP 层（10B 总 / 0.7B 激活）省掉外挂 draft

每层 256 个专家、只激活 8 个，是“细粒度 MoE”的典型配置：专家越多、越专，路由的区分度越高，但负载均衡越难。

IndexCache 与 iHC：两个“小改动”的价值

  • IndexCache：每 4 层复用同一个索引器（与 GLM 的 IndexShare 同源），减少长上下文下重复的索引扫描。参考实现是 arXiv:2603.12201。
  • iHC（identity Hyper-Connections）：改写残差通路，让后层能更直接地访问前层表示，缓解深层信息稀释。

两个都不改变“模型能做什么”，只改变“做到的成本”。2026 年的模型进步，很大一部分就来自这种“效率件”的堆叠。

在机房里看这件事

数据 体积 说明
权重（FP8）770 GB6 张 H200 起，8 卡舒适
每 token 激活49 GB10ms @4.8TB/s → 100 tok/s
MTP 层10B（激活 0.7B）几乎免费的加速器
all-to-all每层 top-8 × hidden × 2B跨节点时是瓶颈
KV（1M，门控 DSA）十 GB 级依赖索引复用

要点：MTP 内置意味着部署时不需要再挂一个 draft 模型，省一次权重加载和一套 KV 管理——这是“工程友好”的具体体现。

Apache 2.0 的分量

在“旗舰模型开始收紧许可证”的 2026 年（例如 Kimi K3 的自定义许可），Hy4 选择 Apache 2.0，对企业的意义是：

需求 Apache 2.0 是否满足
私有化部署✅
闭源再分发✅
托管服务对外售卖✅（无需授权）
专利授权✅（明示）

这种“不设卡”的姿态，通常换来的是更快的生态扩散。

写到这里的判断

  • 结构收敛已经完成，细粒度 MoE + 稀疏注意力 + 索引复用 + 内置 MTP，这四件套会成为 2026-2027 的默认配置。
  • 差异化会转向数据与后训练：结构抄得越快，数据管线和 RL 配方就越关键。
  • Apache 2.0 + 770B/49B， 是很实用的组合：单机 8 卡能跑，法务没负担。
  • 如果你自己部署：先看“有没有内置 MTP 和索引复用”，这两个决定了同硬件下的吞吐差 1.5～2 倍。
