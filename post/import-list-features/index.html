导入函数列表当特征：四条判据和三种做法

2022-10-27·6 分钟·2370 字 安全

一个 PE 文件的导入表通常在 30 到 200 个函数名之间，大半是运行时库的样板。拿它当分类特征要先承认两件事：分布极度倾斜，长尾里多数 API 在语料里出现不到 5 次；内容可以被故意削薄，加壳和动态解析能把导入表缩到十几项。

这两件事决定了特征编码的形状，比选分类器重要。

三种 token 单位的代价

做法 token 单位 维度 每样本非零位 主要失效模式
A 单 API 哈希单个 API 名固定 2^1480–150导入表缩到十几项时向量几乎全零
B API 对哈希(dll, api_i, api_j)固定 2^14300–600长尾 pair 只出现一次，小样本上全是噪声
C DLL 桶统计每个 DLL 取 k 个DLL 数 × k，约 200 × 320–60DLL 相同、函数集完全不同的样本被压成同一点

B 的 token 是三元组，按 API 名排序后拼接，避免 (a, b) 和 (b, a) 变成两个维度。C 按 DLL 聚合，每个 DLL 取出现次数最多的 k 个 API 或只留计数，向量短、可解释，适合粗筛。

三类失效里有两类能提前看见：会不会被削到十几项，看加壳比例；pair 够不够重复，看同族样本条数。判据就是拿这两件事对表里最后一列。

四条判据

维度有界。维度不能跟着词表长。线上的特征维度一旦随新出现的 DLL 变化，模型就得重训，历史向量也没法比较。

缺失可预期。样本没有导入表、只有序数导入、只导入两个解析函数，这些都得有明确定义的表示。把缺失当成零向量是最省事也最糟的处理，它让「什么都没导入」和「导入了一堆但都在低权重位置」长得一样。

能表达组合。单个 API 的区分度接近于零，VirtualAlloc 和 CreateRemoteThread 同时出现才有意义。词袋把这件事丢掉了，所以得往组合上想办法。公开实现里这条路叫特征哈希（hashing trick），把任意多的组合映射到固定维度上，代价是碰撞。

可复现。训练和线上必须是同一个向量，哈希输出得稳定，不能用带进程随机种子的内置实现。四条里只有这一条会在半夜出问题，下面先讲它。

稳定哈希

import hashlib

DIM = 1 << 14

def bucket(token):
    h = hashlib.blake2b(token.encode(), digest_size=8).digest()
    v = int.from_bytes(h, 'little')
    return v & (DIM - 1), 1.0 if v >> 63 else -1.0

def vector(imports):
    vec = [0.0] * DIM
    for tok in imports:              # 已小写、去掉 .dll 后缀
        i, sign = bucket(tok)
        vec[i] += sign               # 符号位抵消一部分碰撞偏置
    return vec

用 blake2b 而不是内置 hash() 是踩过坑的：hash() 对字符串按进程随机加盐，训练进程和线上进程算出来的桶号完全不同，特征全部错位，两边都不报错，只是准确率莫名其妙掉下来。离线评估看不出这个 bug，因为评估和训练在同一个进程里。

符号位是第二个细节。两个 token 撞进同一个桶又都加正数，这个维度的值会系统性偏大，模型学到的是碰撞强度。给每个 token 一个 ±1 的符号，碰撞在期望上互相抵消，代价是单维不再可解释。

冲突账

设语料里不同 token 有 3 万个，维度 16384。桶占用率按 1 - exp(-n/M) 算是 84%，每桶平均 1.83 个 token；碰撞对约 n² / (2M)，即 2.7 万对，占全部 token 对（约 4.5 亿）的 0.006%。

这个量级下 A 方案是够用的，碰撞带来的噪声远小于样本本身的标签噪声。把维度提到 2^18，占用率降到 11%，但向量变长、稀疏索引开销上升，批量打分时是实打实的成本。两个数都是估算，真实影响看验证集上的过拟合。

B 的问题不在碰撞，在覆盖率。3 万 token 两两组合有 9 亿种可能，实际出现的 pair 大多只出现一次。样本量低于 5000 时，能重复出现的 pair 太少，模型学到的是「这条样本见过」。

缺失值不该是零

序数导入。imp.name 为空、只有 imp.ordinal 的情况，用 ord17/kernel32 这样的 token 保留。合法程序为了跨版本兼容很少做纯序数导入，所以这个 token 本身就是信号。丢掉它等于把「这份导入表不正常」这条信息删了。

延迟加载。延迟加载导入在数据目录第 13 项（IMAGE_DIRECTORY_ENTRY_DELAY_IMPORT），不少解析代码只读第 1 项。两类合进同一个集合，另记一个「延迟加载占比」的标量。

完全没有导入表。不要用零向量顶上，给一个显式的 missing 标记，让这批样本走独立分支，别和正常样本混在同一个特征空间里。

上线前先量两个数

第一个是桶占用率，超过 90% 就该加维度或换 token 单位，训练集上直接算。第二个是 pair 重复次数的中位数，低于 3 说明没有统计意义，B 会退化成记忆样本。

样本量给的是粗边界：不到 5000 用 A，5000 到 20 万用 B，只想区分「下载器 / 释放器 / 常规程序」用 C 或 C 粗筛加 A 细排。两条门禁写进训练脚本，不必每次开会决定。
