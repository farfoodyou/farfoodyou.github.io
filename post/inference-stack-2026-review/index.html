年初的 引擎复盘 里，我把推理优化归成四条主线。一年过去，四条都走完了各自的一段路。

前缀缓存：从优化项变成准入项

2025 年，前缀缓存还是“开了更好”；2026 年，长程 agent 的账单把它变成“不开就破产”。

算一笔：

一次 200 步的 agent 任务，上下文 100K token：
未命中缓存：200 × 100K = 20M 输入 token
命中 90%：  20M × 0.1 + 首次 100K ≈ 2.1M 输入 token

差 10 倍。这就是为什么引擎把 KV-aware 路由、RadixAttention、IndexCache 一层层往栈里塞。

配套变化：

组件 2025 2026
路由轮询/QPSKV 感知（哪个副本有这段前缀）
缓存粒度前缀块前缀块 + 跨层索引复用
落盘可选分层（HBM→CPU→NVMe），按命中率动态调整
观测无命中率、复用 token 数成为核心指标

稀疏注意力：吃掉长上下文

指标 2025 2026
1M 上下文的 KV35 GB（MLA）0.89 GB（CSA2 + FP4）
索引开销每层 O(L)每 4 层一次 / 分层候选池
单 token FLOPs @1M基线27%（V4 vs V3.2）

结论：“长上下文”从“能不能”变成“多少钱”。100 万 token 的请求在 2026 年可以做到不到 1GB 的 KV、几秒的 prefill（配缓存）。

并行：集群被拆成两层

2026 年的标准部署形态：

prefill 池（compute-bound）  →   KV 传输（RDMA）  →   decode 池（memory-bound，大 batch）
        ↑                                              ↑
   高算力、低显存                                  高带宽、低算力

配套的是 EP（专家并行）+ PD 分离：

技术 解决什么 代价
TP单机内分摊权重通信密集，跨机不可行
EP万亿 MoE 的专家分布all-to-all，网络敏感
PD 分离两种负载的资源错配KV 传输（GB 级/请求）

KV 传输的量级：100K token × 890B ≈ 89 MB/请求。按 400G（50GB/s）算约 1.8 ms——在 CSA2 这种压缩比下，PD 分离才真正划算；在 35KB/token 的时代，100K 上下文要传 3.5GB，需要 70ms。

量化：FP4 落地

对象 2025 2026
权重FP8 主流FP8 + FP4（B200/新 ASIC）
KVFP16/FP8FP4（E2M1 + per-block scale）
激活FP8FP8（FP4 激活仍少见）

FP4 KV 是今年最实用的单项：显存减半、带宽减半，代价是长文场景要做校准。

代价表：四条主线的取舍

优化 收益 风险 什么时候别做
前缀缓存输入成本 10× ↓命中率低时白占显存请求前缀几乎不重复
稀疏注意力长上下文 2～10× ↓gather 效率低、精度损失短上下文（<8K）纯浪费
PD 分离吞吐 2～5× ↑KV 传输、运维复杂单机就能满足吞吐
FP4 量化显存/带宽 2× ↓精度、kernel 支持任务对数值极敏感

最后说三句

  • 2026 年的性能提升，一半来自结构（稀疏/压缩），一半来自系统（缓存/并行），，纯粹靠硬件的比例在下降。
  • “每 token 读取字节数”会成为最重要的部署指标，比参数量、比榜单都更能预测成本和延迟。
  • PD 分离会在 KV 压缩普及后变得普遍，（传输成本从 GB 级降到 MB 级）。
  • 给团队的一张顺序表：先缓存 → 再量化 → 再稀疏结构 → 最后才 PD/EP。前两步几乎无风险，后两步要重训或重部署。
