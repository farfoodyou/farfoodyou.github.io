Kimi k1.5：长上下文 RL 的另一条路，以及被低估的推理工程

2025-01-23·8 分钟·3327 字 模型

和 R1 同一天（1 月 20 日），月之暗面发布了 Kimi k1.5 的技术报告。两个团队独立走到同一个方向：放弃过程奖励、只用端到端的结果奖励做 RL。但取舍完全不同。

R1 的关键词是“纯”：纯 RL、纯规则奖励。k1.5 的关键词是“长”——把 RL 的上下文拉到 128K，让模型在一个 episode 里自己探索、试错、回退。

故意不做的那三件事

报告摘要里有一句话很关键：他们的框架不依赖 Monte Carlo tree search、value function 和 process reward model，靠的是 “long context scaling 与 improved policy optimization”。

这三个组件恰是 2024 年推理模型论文的标配：

组件 传统做法 代价 k1.5 的选择
MCTS搜索树展开 + 回溯每步多次前向，rollout 成本爆炸不做，靠长 CoT 隐式搜索
value function估计中间状态价值依赖标注或 bootstrapping，误差累积不做，只信最终结果
PRM逐步打分人工标注贵、容易被 hack不做，只给结果奖励

他们的论点是：只要上下文够长、策略优化够稳，模型能自己学出“隐式搜索”。 换句话说，把搜索从 inference 挪回 training。

长上下文 RL 的两个硬骨头

把 RL 的 rollout 长度从 4K 拉到 128K，会同时遇到两个工程问题。

第一，长度膨胀。 CoT 越长，reward 的归因越难，策略容易学会“无脑多写”。报告的处理是给 rollout 设 token 预算、加长度惩罚，并课程式地逐步放长。

第二，长尾请求。 一个 batch 里既有 128K 样本，也有 2K 样本，同步等待就是灾难。他们用 partial rollout：某个样本超预算就先截断、放回队列，下一轮从截断处继续采样。长样本不阻塞整个 batch，已生成的 token 也不浪费。

while unfinished_trajectories:
    batch = runnable_trajectories(token_budget)     # pack by budget
    out   = infer_engine.generate(batch, max_new_tokens=chunk)
    for traj in out:
        if traj.hit_eos:      rl_batch.add(traj); score(traj)
        elif traj.hit_budget: persist(traj); requeue(traj)
        else:                 keep_generating(traj)

论文里有专门一节讲 rollout 基础设施（§3 Infra）。配套的是训练与推理同源：rollout 走 vLLM 这类推理引擎（continuous batching、PagedAttention），训练走 Megatron 类框架，中间靠权重同步衔接。同步开销、精度对齐（训练 bf16 / 推理 fp8）、chunked prefill，全是脏活。

这些东西在论文里只占一小节，但它是“能不能跑起来”的分界线。

策略优化：镜像下降，而不是 PPO

k1.5 用的不是标准 PPO，而是 online mirror descent 的一个变体（报告里称为 improved policy optimization）。直觉上的区别：

  • PPO 在参数空间做一阶梯度 + clip，信赖域是“软”的；
  • mirror descent 在分布空间做更新，天然带 KL 投影，长序列上的方差更小。

报告把它和“长度惩罚 + 数据配比”一起列为长 CoT RL 能收敛的关键。这个选择和 R1 的 GRPO 走的是不同分支，目标一致：在没有 critic 的前提下压住方差。

long2short：把长思考的收益搬回短模型

这是产品化最值钱的部分。线上延迟就是成本，128K 的 CoT 不可能直接卖给用户。

报告给了四种把长 CoT 能力“压缩”进短输出的方法：

  1. model merging：把长 CoT 版本与短 CoT 版本的权重做融合；
  2. shortest rejection sampling：同题采样多次，只留最短的正确解做 SFT；
  3. DPO：用“正确且更短”作为偏好对；
  4. length penalty：训练时对长度直接加惩罚。

效果（摘要给出的口径）：

指标 long-CoT k1.5 short-CoT k1.5
AIME77.560.8
MATH-50096.294.6
LiveCodeBench—47.3
Codeforces94 百分位—
MathVista74.9—

短 CoT 版本在 MATH-500 上 94.6，报告原话是比 GPT-4o、Claude 3.5 Sonnet 高出 “up to +550%"——这是相对提升，别理解成绝对分数。AIME 60.8 也已经远超同代非推理模型。

这个思路值得单拎出来：先训一个“想很久”的教师，再把思考过程蒸馏/压缩成“想一会儿”的学生。R1 用蒸馏做小模型，k1.5 用 long2short 做短输出，本质是一回事，只是压缩的对象不同（参数 vs 思考长度）。

多模态是一起训的

k1.5 是原生多模态：文本和视觉数据在训练与 RL 阶段一起进（摘要里写作 “multi-modal data recipes”）。视觉 RL 的收益不只是“看图答题”，而是让模型在推理过程中把图像当工作内存用——比如几何题里反复核对图形标注。

MathVista 74.9 是这个量级上的强结果。这条线后面会被各家推到极致，但 k1.5 是最早把“视觉 + 长 CoT RL”拼起来公开的之一。

和 R1 对着看

维度 DeepSeek-R1 Kimi k1.5
冷启动有（R1），无（R1-Zero）有
策略优化GRPO（组内归一化，无 critic）online mirror descent 变体
奖励规则奖励（准确率 + 格式）结果奖励 + 长度惩罚
RL 上下文32K～64K 量级128K
推理侧工程强调蒸馏、把能力下放小模型强调 partial rollout、训练推理同源
交付形态全权重开源（MIT）API + 报告（权重未开）

两条路都对，气质不同：R1 是“把方法公开，让社区去压成本”；k1.5 是“把工程做厚，先保证线上能跑”。短期看后者变现更快，长期看前者的生态会更大——权重是否开放，决定别人能不能在你之上继续叠。

落到工程上，我的判断是这样：

  1. 算法上没有神秘配方：不做 PRM、不做 MCTS 已经成为共识，差异落在数据配比和训练稳定性上。
  2. 长上下文 RL 的瓶颈在 infra，不在 loss。 partial rollout 这类“实现细节”决定 batch 利用率是 30% 还是 80%。
  3. long2short 被严重低估。 榜单只看 long-CoT，产品只买得起 short-CoT；把 77.5 压成 60.8 且延迟降一个数量级，商业价值可能大于再涨 3 分。
  4. 权重不开放，影响力就要打折。 这一条等半年再看。
