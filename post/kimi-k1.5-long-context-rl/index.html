Kimi k1.5：长上下文 RL 的另一条路，以及被低估的推理工程

2025-01-23·6 分钟·2480 字 模型

和 R1 同一天（1 月 20 日），月之暗面发布了 Kimi k1.5 的技术报告。两个团队独立走到同一个方向：放弃过程奖励、只用端到端的结果奖励做 RL，但取舍完全不同。

R1 的取舍是“纯”：纯 RL、纯规则奖励；k1.5 的取舍是“长”——把 RL 上下文拉到 128K，让模型在同一个 episode 里自己探索、试错、回退。

故意不做的那三件事

报告摘要：框架不依赖 Monte Carlo tree search、value function 和 process reward model，靠的是 “long context scaling 与 improved policy optimization”。

组件 传统做法 代价 k1.5 的选择
MCTS搜索树展开 + 回溯每步多次前向，rollout 成本爆炸不做，靠长 CoT 隐式搜索
value function估计中间状态价值依赖标注或 bootstrapping，误差累积不做，只信最终结果
PRM逐步打分人工标注贵、容易被 hack不做，只给结果奖励

论点是：只要上下文够长、策略优化够稳，模型能自己学出“隐式搜索”。搜索被从 inference 挪回了 training。

长上下文 RL 的两个硬骨头

把 rollout 长度从 4K 拉到 128K，会同时遇到两个工程问题。

长度膨胀。 CoT 越长，reward 归因越难，策略容易学会“无脑多写”。报告的处理是给 rollout 设 token 预算、加长度惩罚、课程式逐步放长。

长尾请求。 一个 batch 里既有 128K 样本也有 2K 样本，同步等待就是灾难。他们用 partial rollout：样本超预算就先截断、放回队列，下一轮从截断处继续采样。长样本不阻塞整个 batch，已生成的 token 也不浪费。

for batch in token_budget_chunks(runnable):          # pack by budget
    for traj in infer_engine.generate(batch, max_new_tokens=slice):
        if traj.hit_eos:      rl_batch.add(traj); score(traj)
        elif traj.hit_budget: persist(traj); requeue(traj)   # 存下截断点
        else:                 keep_generating(traj)

配套的是训练与推理同源：rollout 走 vLLM 这类推理引擎（continuous batching、PagedAttention），训练走 Megatron 类框架，中间靠权重同步衔接。同步开销、精度对齐（训练 bf16 / 推理 fp8）、chunked prefill，全是脏活。论文里只占一小节（§3 Infra）。

策略优化：镜像下降

k1.5 用的是 online mirror descent 的一个变体。差别在信赖域的形态：PPO 在参数空间做一阶梯度加 clip；mirror descent 在分布空间更新，天然带 KL 投影，长序列上的方差更小。和 R1 的 GRPO 是不同分支，目标一致：没有 critic 也要压住方差。

long2short：把长思考搬回短模型

128K 的 CoT 不可能直接卖给用户。报告给了四种压缩办法：model merging（长/短权重融合）、shortest rejection sampling（只留最短的正确解做 SFT）、DPO（把“正确且更短”作偏好对）、length penalty。

指标 long-CoT k1.5 short-CoT k1.5
AIME77.560.8
MATH-50096.294.6
LiveCodeBench—47.3

短 CoT 版本在 MATH-500 上 94.6，报告原话是比 GPT-4o、Claude 3.5 Sonnet 高出 “up to +550%”，这是相对提升，别读成绝对分数。AIME 60.8 也已远超同代非推理模型。

先训一个“想很久”的教师，再把思考压成“想一会儿”的学生：R1 用蒸馏压参数，k1.5 用 long2short 压思考长度，对象不同，收益同源。

多模态是一起训的

文本和视觉数据在训练与 RL 阶段一起进（摘要写作 “multi-modal data recipes”）。视觉 RL 的收益不只是“看图答题”：几何题里反复核对图形标注，图像被当成工作内存用。MathVista 74.9 是这个量级上的强结果，也是最早把视觉与长 CoT RL 拼起来公开的工作之一。

R1 把方法公开，让社区去压成本；k1.5 把工程做厚，先保证线上能跑。如果只抄一件，我抄 partial rollout 的队列设计：算法侧已经没有配方差，差别全在 batch 利用率（30% 还是 80%）和权重同步这两处脏活上。
