Kimi K2：1T MoE 全权重开源，以及 Muon 优化器的一次大考

7 月 11 日，月之暗面开源 Kimi K2。规格：

项目 数值
总参数 / 激活参数1T / 32B（MoE）
训练 token15.5T
上下文128K
许可证Modified MIT
定位"reflex-grade model without long thinking"

最后一行很有意思：它故意不做长思考。在所有人往 reasoning 上冲的时候，K2 把自己定位成“快速反应 + 会用工具”的 agent 底座。

Muon 优化器的规模化

K2 的技术重点写在模型卡的第一条：在 1T 参数规模上用 Muon 优化器，并且零训练不稳定（报告 与 模型卡）。

Muon 和 AdamW 的差别在对梯度矩阵的处理：AdamW 逐元素做二阶矩归一化，Muon 对矩阵做近似正交化（Newton–Schulz 迭代），让更新方向更“均匀”。它在小模型上早有好结果，但大规模上的问题是数值爆炸——1T 参数、15.5T token 的训练里，只要有一个 head 的 attention logits 翘起来，整个 run 就废了。

他们的解法是 MuonClip：

every step:
  if max(attention_logits) > tau:          # tau = clip threshold
      q_proj *= tau / max_logit            # rescale QK projections
      k_proj *= tau / max_logit
  update with Muon(orthogonalized gradient)

思路很工程：不去改 loss，也不加辅助正则，而是在检测到越界时直接把权重缩回来。代价是每次 forward 多一次 max 归约（可融合进 flash attention 的 log-sum-exp 路径），收益是整个训练过程不需要为稳定性调参。

这条经验值得抄的地方在于：大模型训练的大部分事故不是“学不会”，而是“发散”。任何能在不改变优化目标的前提下把数值钉住的技巧，都比换算法更实用。

15.5T token 与 agentic 数据

15.5T 的语料规模接近“能公开拿到的全部高质量文本”的极限。再往上堆，边际收益很低——所以 K2 的重心放在数据质量与合成：

  • 大量工具调用轨迹（多轮 function call、失败重试、错误处理）；
  • 代码仓库级任务（跨文件修改，而不是单函数补全）；
  • “agentic" 数据合成管线：用强模型生成任务 + 用环境执行验证，只留成功的轨迹。

这解释了为什么它的定位是 agent 底座：训练数据里就写满了“怎么用工具”。

1T MoE 的部署现实

精度 权重体积 最小可用集群
FP8~1 TB8 × H200（141GB）或 16 × H100
INT4~500 GB8 × H100（勉强）
BF16~2 TB32 × H100

也就是说：开源不等于可自托管。能跑得动 K2 的团队，全球数量有限。它的真实作用是：

  1. 给闭源 API 定价施加压力；
  2. 让有卡的机构（云厂商、大企业）能私有化部署；
  3. 提供一套可复现的配方，让小模型团队抄思路。

对照 671B/37B 的 DeepSeek 系列，1T/32B 的稀疏度更高：激活比例只有 3.2%。稀疏度越高，单 token 算力越省，但对显存容量和专家负载均衡的要求越高。

K2-Instruct 明确是“没有长思考的反射级模型”。2025 年 7 月的时点上，这是一个反共识的选择：

  • 长思考的收益集中在数学/竞赛/复杂调试；
  • 代价是延迟和成本翻几倍，且对 agent 循环不利（每步都等 30 秒，多步任务没法用）；
  • agent 场景里 80% 的步骤是“读文件/调接口/改一行”，不需要深思。

所以 K2 的路线是：先做一个又快又稳的执行者，把思考留给需要的地方（后续的 K2-Thinking 补上了这一块）。这个分工和 Claude 的 Sonnet/Opus、Gemini 的 Flash/Pro 是同一逻辑，只是 K2 是从“完全不思考”起步。

没测出来的

MuonClip 的 clip 阈值 tau 是全局一个还是分层设，报告没写；1T 规模上这个超参的敏感区间有多宽，也没有扫参结果。官方说“零不稳定”，但没公开 loss 曲线分阶段的细节，所以 Muon 能不能推到 3T，现在只能算猜测。还有一条我确实不知道答案：激活比例从 3.2% 再压到 2%，路由退化的临界点在哪里，取决于训练 token 与专家数的配比，K2 这一版没有给对照组。

两组数放在一起

把 K2 和上一代 671B/37B 的部署账并排放：总参数从 671B 涨到 1T（+49%），权重从 671GB 涨到 1TB，但每 token 要读的激活权重只从 37GB 降到 32GB，H200 上对应 7.7ms 和 6.7ms 的 decode 单步——参数多了一半，单流延迟只省 13%。稀疏化的收益落在算力侧（每 token FLOPs 少 14%），不在带宽侧；真要降单流延迟，得靠更狠的量化：INT4 后 32B 激活只占 16GB，单步掉到 3.3ms，代价是精度要重新评。
