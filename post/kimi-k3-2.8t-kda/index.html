Kimi K3：2.8T 参数 + KDA，开源第一次摸到 3T 级

7 月 16 日，月之暗面开源 Kimi K3：2.8T 参数、1M 上下文、原生视觉（文本/图像/视频同一模型）。

模型卡自称“世界首个开放的 3T 级模型”，两个技术名词值得拆开看：KDA（Kimi Delta Attention） 与 AttnRes（Attention Residuals）。同家族的上两代分别见 K2 与 K2.6。

KDA：把线性注意力做成“可更新状态”

线性注意力的核心是一个固定大小的状态 S，每来一个 token 做一次更新。最朴素的累加形式记忆衰减很快（远的信息被不断覆盖），所以工程上要加“遗忘/写入”的旋钮。

Delta 规则（delta rule）的思路是：不要只累加，而是显式地“纠正”状态——把新 key 投影到当下状态上，算出预测误差，再按误差更新。用伪代码表达：

for each token t:
    pred  = S @ k_t                          # predict from current state
    delta = v_t - pred                       # error term
    S     = S + beta_t * outer(delta, k_t)   # write by error
    o_t   = S @ q_t

好处是状态更新有“目标”（逼近 v），不会像纯累加那样漂移。代价是每步多一次矩阵-向量乘，算力略增，但显存仍是常数。

对 1M 上下文的意义：KV 不随长度增长，decode 每 token 只读固定状态，带宽友好。

AttnRes：给层间加“残差注意力”

Transformer 的残差是逐元素的加法；AttnRes 把“跨层信息混合”做成注意力形式——后层可以直接“读”前面若干层的表示，而不只是继承一个累加和。

这对超深网络（2.8T 参数通常意味着很深的堆叠）有价值：缓解深层的信息稀释，让梯度路径更短。今年多个团队在残差连接上做文章（包括 Hy4 的 iHC），说明“残差是下一个可优化点”已经成为共识。

数据 体积 现实含义
权重（FP8）2.8 TB≥20 张 H200 / 16 张 B200，跨节点
每 token 激活未公开（K2 家族为 32B 级）若按 32B 估：6.7ms @4.8TB/s
KV（1M，KDA）常数级（不随长度涨）长上下文的核心优势
视频/图像 token每帧数百至数千视觉编码开销另算

有三处值得记下来：

  1. 2.8TB 权重不可能单机，必须跨节点 + 专家并行；网络拓扑直接决定可用性。
  2. KDA 让 1M 上下文的 KV 成本可预测，这是它敢标 1M 的底气（对比 GQA 的数百 GB）。
  3. 原生视频推理的 prefill 成本极高：一分钟视频可能几十万 token，实际产品必须做抽帧/摘要。

许可证：不是 MIT

K3 用的是自定义的 Kimi K3 License（license_name: "kimi-k3"），不是 K2 的 Modified MIT。这在 2026 年是一个趋势：旗舰开源模型开始收紧条款（月活、商用规模、再分发）。

对企业的影响很实际：

条款类型 影响
MIT / Apache 2.0法务直接过，可闭源再分发
Modified MIT（署名）需要标注来源，通常可接受
自定义许可（K3 类）需逐条评估，可能限制托管服务

模型卡里的那句话

模型卡写的是“世界首个开放的 3T 级模型”。同一句里更重要的是下一行：license_name: "kimi-k3"。K2 那版用的还是 Modified MIT，K3 换成了自定义条款，于是“开放”这个词能承载的东西少了一截——权重可以下载、可以自跑，能不能托管给第三方卖，要逐条读。

判断一个权重能不能进生产，读 license_name 比读标题有用。

至于 3T 级本身，能跑它的机构屈指可数，这类模型的现实用法是摸 API 供应商的成本底线，不是自己部署。长上下文逼着大家动结构，线性注意力加残差改造这条线，2027 年之前都会有人接着改。
