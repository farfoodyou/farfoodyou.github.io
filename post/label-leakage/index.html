切分里漏出去的那部分：标签泄漏与家族级切分

2023-04-11·6 分钟·2449 字 安全

分组交叉验证的文档里有一句不起眼的注释：同一个分组不会同时出现在两个折里。这句话在多数教程里被当作可选参数提一下，在我这里它决定了整个离线评估还有没有意义。

文件检测的样本库有个绕不开的性质：恶意样本是成族出现的。一个家族的几百个变体共享同一个打包器、同一段加载器、同一批回连域名，甚至编译时间戳只差几分钟。随机切分把同一族的变体分到训练集和验证集，模型学到的是「这个家族的指纹长这样」，而不是「这类行为可疑」。离线指标很好看，上线当周就掉回去。

数据流从哪一步开始漏

样本入库存四类信息：文件本身的静态特征、沙箱跑出来的行为序列、首次出现时间、外部给的家族标签。特征由三个作业分别产出，再按样本标识 join 成一张宽表。

泄漏点沿着这条链分布，每一处都很自然，自然到看不出来：

  • join 键太粗。用「同源簇」做邻居统计特征时，簇是按样本相似度聚出来的，一个簇里往往就是同一家族的变体。验证集样本的簇统计里含了训练集样本的标签，这是最隐蔽的一类，特征本身长得像正常的上下文统计。
  • 时间字段进特征。首次出现时间被当成数值特征喂进去，训练集里它的分布和标签强相关（老家族已经打标，新家族还没有），线上推理时这个字段要么拿不到，要么含义不同。
  • 聚合窗口跨过切分点。类别编码、均值填充这类统计量在切分之前用全量数据算了一遍。特征选择的文档把这件事讲得很直白：在切分之外做选择或拟合，评估结果会系统性偏乐观。编码比选择更容易漏，因为它藏在一个 fit_transform 里。
  • 近似重复样本。同一份样本改几个字节重新提交，哈希不同，特征几乎一样。按行随机切分，训练和验证各拿一半。

四个点叠加的效果是：验证集不再是「没见过的样本」，而是「见过的家族的新变体」。

把切分改成两层约束

顺序是先时间、后家族。时间切分决定训练能看到什么，家族切分决定验证能考什么。

def walk_forward(rows, k=5):
    # 先按时间切成 k 段连续窗口
    rows = sorted(rows, key=lambda r: r["first_seen"])
    size = len(rows) // k
    slices = [rows[i * size:(i + 1) * size] for i in range(k)]
    for i in range(1, k):
        test = slices[i]
        test_fams = {r["family"] for r in test}
        # 早窗口里的同族样本整族摘掉，整族只落在一侧
        train = [r for s in slices[:i] for r in s if r["family"] not in test_fams]
        yield train, test

for train, test in walk_forward(rows):
    assert max(r["first_seen"] for r in train) < min(r["first_seen"] for r in test)
    assert not {r["family"] for r in train} & {r["family"] for r in test}

两个 assert 是整段代码里最有用的部分：一个管时间，一个管家族。它把「有没有漏」从人的判断变成机器的判断，后面任何人改切分逻辑，只要越界就当场失败。

代价得说清：折数从 5 降到 4，第一段没有更早的训练集；跨窗口的老家族会被整族摘出训练集，样本利用率掉一截。换来的是评估口径站得住。

剩下的配套约束是时间比较要用 datetime，不用月份字符串；家族标签缺失的样本归不进任何族，单独抽出、不参与训练，因为线上这类样本的行为和已标注的不一样。

三种切分方式的落差

样本池是 12 个月、240 万份、3800 个家族，阳性率 3.5%，指标口径都是同一份特征集、同一个模型参数。

切分方式 离线 AUC 验证集与线上的家族重合度 上线首周 precision（复核队列前 1%）
随机五折0.9987%0.41
按时间切成前后段0.9634%0.62
时间约束 + 家族级切分0.948%0.71

那 0.05 的落差不是模型变差了，是评估变诚实了。重合度这一列是我后来才加的，它比 AUC 更能解释线上表现：重合度越高，离线数字越不可信。

线上分布漂移怎么盯

家族级切分解决了训练期的问题，解决不了上线后的问题。新家族占比是逐月变化的，我拉了半年的数据，从 6% 涨到 21%，而训练集里新家族只占 9%。模型对「训练时没见过的东西」天然保守，分数会整体压低，阈值不变就会漏。

现在有三条监控，都很便宜：

  • 每周算一次验证集和最近一周线上样本的单特征分布，用分位数的相对偏移做阈值，超过 0.3 就人工看一眼；
  • 单独统计「分数落在阈值附近正负 10% 区间」的样本比例，这个比例突然变大意味着分布移动了；
  • 把上周线上被判为正的样本回流入下一轮训练，但只回流有复核结论的，且回流样本一律进训练集、不进验证集。

第三条最容易做错。回流样本的标签来自复核，复核队列本身是被模型排序过的，于是训练集逐渐偏向模型已经会判的那部分。我现在的做法是回流时按家族分层抽样，每个家族最多回 200 份，压住这个正反馈。
