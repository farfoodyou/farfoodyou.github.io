LongCat-2.0：1.6T 模型，全程在 ASIC 上训完

2026-06-30·4 分钟·1631 字 模型

目录

6 月 30 日，美团开源 LongCat-2.0（MIT）：1.6T 总参数 / 48B 激活，35T token，支持 1M 上下文（用数百 B token 的 1M 语料专门训过）。

模型卡里最“反常识”的一句话不是参数，而是：

整个训练与大规模部署都建立在 AI ASIC 超节点上，预训练跨越数百万加速器·天，没有回滚，也没有不可恢复的 loss 尖峰。

ASIC 训练意味着什么

大模型训练通常绑定 NVIDIA（CUDA 生态、NCCL、各种 kernel 库）。换成 ASIC 意味着整条栈都要重做：

层次 换 ASIC 要重做的事
算子GEMM/Attention kernel 要重写（没有 cuBLAS/FlashAttention）
通信集合通信原语（all-reduce/all-to-all）要适配互联拓扑
并行TP/PP/EP 的切分策略要按实际带宽重新调
稳定性数值行为不同，loss spike 模式不同
可观测profiling 工具链要重建

“没有回滚”这句话的分量在这里：大模型训练常见做法是“发现 spike，回滚 checkpoint 调参重跑”，回滚一次损失几天到几周。能在新硬件上一次跑完 35T token，说明数值稳定性和故障恢复都做扎实了。

稀疏度“越过甜区”

模型卡里有一句判断：“The sparsity of MoE has crossed the sweet spot." 1.6T / 48B ≈ 3% 激活比例，比 GLM-5（744B/40B ≈ 5.4%）更稀。

稀疏度提高的好处与代价：

稀疏度 单 token 成本 显存需求 专家负载均衡难度
5%（40/744）中744GB中
3%（48/1600）更低1.6TB高
<2%最低更大很高（路由退化）

3% 基本是“还能稳定路由”的边界：再稀，专家会明显欠训练，长尾能力掉得厉害。

数据怎么搬：1.6T 的机房现实

数据 体积 说明
权重（FP8）1.6 TB≥12 张 H200，或 9 张 B200；跨节点几乎必然
每 token 激活权重48 GB10ms @4.8TB/s → 100 tok/s
MoE all-to-all每层 8 专家 × hidden × 2B跨节点走 RDMA，这是主要瓶颈
1M 上下文 KV数十 GB（LongCat Sparse Attention）需要 KV 分层

三点：

  1. all-to-all 是命门。48B 激活分散在十几张卡上，每个 token 的 hidden 要在专家之间搬；按 hidden 7168、top-8、2B 算，每层约 114KB/token，几十层就是每 token 数 MB。
  2. rail-optimized 拓扑比 FLOPs 重要。跨机 all-to-all 的延迟对拓扑极度敏感，同等 GPU 数量下不同组网能差 2 倍。
  3. 部署成本 >> 训练成本。训练是一次性的，部署是长期的；1.6T 模型的推理集群需要持续供电与运维。

再往下看，开源万亿俱乐部的现状（2026-06）：

模型 总/激活 协议 特点
LongCat-2.01.6T / 48BMITASIC 训练、1M 上下文
Kimi K2.61T / 32BModified MITagent swarm
GLM-5.2744B / 40BMITIndexShare
DeepSeek-V4-Pro1.6T / 49BMITCSA + HCA
Hy4 preview770B / 49BApache 2.0Gated DSA + IndexCache

开源已经进入“万亿是标配”的阶段，真正的差异在：许可证、长上下文效率、以及能不能在非 NVIDIA 硬件上跑。

模型卡最后那一句

模型卡末尾写的是“the whole run completed without a single restart”，这句话比前面所有参数都更像结论：这条非主流栈的数值稳定性已经能撑住 35T token 不重启，剩下的差距才轮到生态，算子库、profiler、以及换一次硬件就要重做一遍的那些适配。1M 上下文那一段也顺带说明了成本落在哪：模型结构只决定能不能吃长文，贵的那一段是几百 B token 的长文语料怎么筛、怎么标、怎么配比，这部分没人开源。
