恶意 PDF 的结构与检测：一段增量更新让两条链路同时漏判

12 月 6 日 21:14，邮件通道的样本队列进来一批附件，四十多个文件，同一波投递。检测引擎给的结论是「可疑，无恶意行为」：静态提取器吐出 /Producer、几组字体名、一些解压后像表单文字的片段；沙箱跑满两轮，日志里只有一个进程读过文件，没有子进程，没有出网。按当时的策略这个组合可以自动放行，它们于是在队列里躺了十一个小时，直到有人手动打开其中一个，阅读器弹了「此文档包含脚本」。

脚本完整：/OpenAction 指向的 JS，读 app.viewerVersion，拼一段下载地址，用 exportDataObject 把内嵌文件写盘。

静态提取漏在哪

PDF 的结构不复杂：header、一串 n g obj 对象、一张交叉引用表、一个 trailer，尾部 startxref 给出 xref 偏移。麻烦出在「一张」上。

增量更新允许在文件末尾追加对象和新的 xref 段，新 trailer 的 /Prev 指回上一段偏移，同一对象号出现两次时后写的生效。这条链可以有十几段，每段相当于一次「另存为」，正好够先放个干净版本过扫描再追加。

我们漏掉的是两层叠加。索引器从 startxref 出发只读了一段 xref，把 /Prev 当元信息记下来，没有继续走；样本是第三次增量更新，脚本对象在最后一段。就算走完链，脚本对象还躺在 object stream 里——PDF 1.5 之后对象可以被 FlateDecode 压进 /Type /ObjStm 的流，明文 grep /JavaScript 什么都找不到。这批 40 个样本有 26 个用了对象流。

还有一层更细：name 允许 #xx 十六进制转义，/JavaScript 能写成 /#4AavaScript，字面匹配的规则集整片失效。

def build_index(f, start):
    objs, visited, off = {}, set(), start
    while off is not None and off not in visited:   # 防环
        visited.add(off)
        f.seek(off); head = f.readline()
        if head.startswith(b'xref'):
            entries, trailer = parse_xref_table(f)
        else:
            entries, trailer = parse_xref_stream(f, int(head))
        objs.update(entries)        # 后写的段覆盖先写的
        off = trailer.get('Prev')
    return objs

段数上限当时定 64。缺任一条，一个 3KB 的畸形文件就能让解析线程卡死。

沙箱为什么也是空的

那两轮执行的都是「打开，观察」。PDF 脚本并不保证打开时执行：/OpenAction 是最常见的自动路径，但这一批样本挂在文档级 /AA 的 /WC（关闭窗口）上，另有一份挂在表单域的 /AA /K（按键）。渲染器只在对应交互发生时才派发事件，我们没做任何交互。

观测面也缺。日志只抓进程、文件、网络，而 JS 里的字符串拼接、把内嵌文件写盘都在渲染器进程内部完成，得 hook 到文档 API 层才看得见。只看 syscall，等于隔着两层。

两条链路是同一种错：把「我没看见」当成「不存在」。静态看不见，因为索引不全；动态看不见，因为没触发。

改了什么

  1. 索引层：走完 /Prev 链（含 xref stream），带环检测与段上限，对象表按后写覆盖合并；每个 /ObjStm 解压后建二级索引。
  2. 解码层：#xx 反转义后再匹配名字；流过滤器按链解（Flate 解完再看内层 ASCIIHex）；解压设单流上限 32MB、膨胀比上限 200:1，避免解析器被自己的解压路径打穿。
  3. 规则层：从「匹配字面名字」改成「匹配对象图上的位置」，例如「文档级 /AA 下任意键，其 /S 为 /JavaScript」。规则描述载体位置而不描述拼写，转义和别名就绕不过去。
  4. 沙箱：加固定触发序列（打开、停 3 秒、点第一个表单域、翻页、关闭），并把静态抽出的 /EmbeddedFiles 与 /Launch 目标当子样本独立送检。

加密那条线当时也不干净：空口令加密的样本，字符串和流都是密文，而解开只要按规范算一遍密钥。后来做成强制预处理，先试空口令，失败才转人工。

两条链路各自的盲区

静态结构提取 动态沙箱
单样本成本毫秒级，可全量跑分钟级，受配额约束
能覆盖所有能解析出来的对象，含未执行分支只有真的执行到的路径
典型盲区未知过滤器、未实现的特性、漏洞利用本身时间与环境门槛、缺交互、无 GUI 事件
错误信号解析抛错被当成「没有」无日志被当成「干净」

判据两条：静态解析失败的样本不进自动放行；静态有脚本而沙箱零行为的进人工队列。量级不到样本总量的百分之一。

更难的是脚本完全不存在、恶意在渲染器内存损坏路径里的形态，静态只能看到一个畸形字体表或一张超大的 JBIG2 图。这类样本在沙箱里通常表现为渲染进程崩溃而不是行为日志，所以崩溃事件也得算可疑。
