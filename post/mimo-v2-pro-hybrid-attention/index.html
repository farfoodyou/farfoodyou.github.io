3 月 18 日，小米发布 MiMo-V2-Pro。规格先摆：

项目 数值
总参数 / 激活>1T / 42B
上下文1M token
注意力混合注意力，比例 7:1（前代 5:1）

发布前它以 Hunter Alpha 的代号挂在 OpenRouter 上，一度被社区当成 DeepSeek 的新模型——这个插曲比参数更能说明 2026 年的模型生态：大家都先匿名放权重，看真实流量反馈再开发布会。

混合注意力 7:1 是什么意思

混合注意力 = 大部分层用线性注意力（省带宽、省显存），少部分层保留 softmax 注意力（保精确检索）。比例 7:1 意味着每 8 层里有 7 层是线性的。

这个方向 2025 年就有（MiniMax 的 lightning attention 是纯线性 + 少量全注意力），2026 年的变化是比例往线性一侧加码：

结构 每 token KV 1M 上下文 KV 检索精度
全 softmax（GQA）数百 KB数百 GB最好
5:1 混合显著降低数十 GB好
7:1 混合更低十 GB 级略降
纯线性常数常数明显下降

7:1 的选择说明一件事：在 1M 上下文这个量级，精度损失可以接受，显存和带宽不能妥协。

MTP：一次前向出多个 token

MTP（Multi-Token Prediction）不是新概念（DeepSeek-V3 训练时就用过），但把它做成轻量推理层是 2026 年的工程趋势：

标准 decode：  前向一次 → 1 个 token
MTP decode：   前向一次 → 主干 token + 投机草案 → 验证 → 一次接受多个

本质上它是投机解码的内置版本：模型自己猜后面几个 token，再用主干并行验证。收益取决于接受率，通常 1.5～2.5× 吞吐。

代价：

  • 显存多一份 MTP 头（小）；
  • 接受率低时白算，延迟反而变差；
  • 对采样温度敏感（高温时接受率下降）。

带宽视角：1T/42B 的账

数据 体积 路径 谁在搬
常驻权重1T × 1B(FP8) ≈ 1 TBHBM 常驻加载一次
每 token 激活权重42B × 1B ≈ 42 GBHBM → SMEMTMA / cp.async
1M 上下文的 KV混合注意力下十 GB 级HBM ↔ SMEM稀疏/gather 访问
MoE all-to-all每层 8 专家 × hidden × 2BGPU ↔ GPUNVSHMEM / NCCL

硬指标：

  • 容量：1TB 权重至少 8 张 H200（141GB，合计 1.13TB）——几乎没有余量给 KV，实际要 2 个节点（16 卡）；
  • 单流 decode：42GB / 4.8TB/s ≈ 8.8 ms/token → 约 110 token/s；开 MTP 且接受率高时可到 200+；
  • 长上下文 prefill：1M token 的一次 prefill 是数十秒级，必须配合前缀缓存，否则交互式产品没法用；
  • 跨节点 EP：16 卡跨机时，专家并行的 all-to-all 走 RDMA，网络拓扑（rail-optimized）比 FLOPs 更决定吞吐。

直白点讲：1T 参数 + 1M 上下文在 2026 年仍然不是“一台机器”的东西。

再往下看，为什么大厂都在做“agent 大脑”：

官方定位是“agent 系统的 brain”，官方给的对标也很直白：编码能力超过 Claude Sonnet 4.6，通用 agent（ClawEval）接近 Opus 4.6。

这背后的判断是：agent 的价值不在单轮回答，而在长任务里的稳定性。所以 2026 年旗舰模型的卖点从“知识/推理分数”转向：

  • 工具调用稳定性（不乱传参、不重复同一错误）；
  • 长上下文下的目标保持；
  • 多步任务的成功率曲线；
  • 单位任务成本。

这些能力没有统一榜单，只能靠 ClawEval、Terminal-Bench 这类“带环境”的基准，加上自家任务集。

不确定的部分

  • 混合注意力会继续往线性侧偏，7:1 可能还不是终点；代价是检索型任务（长文档精确问答）需要外挂检索，而不是指望注意力。
  • MTP/投机解码会变成引擎默认，2026 年下半年不开投机解码的部署基本等于浪费 GPU。
  • “匿名放权重”会成为发布常态，真实流量比发布会更能验证 agent 能力。
  • 如果你自己部署：1T 级模型的意义是“能不能私有化”，不是“能不能省 API 费”。评估时先算网络与运维成本，再算 GPU。
