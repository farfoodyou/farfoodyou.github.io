非常驻代码：节表里那块只有虚拟大小的内存

2022-10-11·6 分钟·2471 字 安全

节头里 SizeOfRawData 和 VirtualSize 不是一回事：前者是这节在文件里占多少字节，后者是加载后占多少，规范明确允许前者小于后者，差出来的部分由加载器补零。写解析器时我把这条当边角情况，直到看到一个样本的末节 VirtualSize 是 0x2A000，SizeOfRawData 只有 0x400。

磁盘上 1KB，内存里 168KB，中间那 167KB 没有文件字节。它可以是普通的未初始化数据，问题是这节带 MEM_EXECUTE。

加载器实际做的五步

  1. 读 SizeOfImage，保留这么大一段地址空间。
  2. 逐节映射：文件里有字节的从 PointerToRawData 拷 SizeOfRawData 字节，没有的补零，权限取 Characteristics。
  3. 镜像没落在 ImageBase 上时，按基址差值修正重定位项。
  4. 遍历导入表，把每个 IMAGE_IMPORT_DESCRIPTOR 的 thunk 填成真实地址。
  5. 跳到 AddressOfEntryPoint。

加载器信任的东西全在头部：SizeOfImage、节表、重定位表、导入表。它不检查节里的字节是不是代码，也不检查入口点那节在文件里有没有内容。

地址落空的那一段

从文件视角看，内存地址落在节里的归宿只有三种（头部另算）：

RVA 落点 文件里有字节 谁来填 检测含义
[VA, VA + min(VirtualSize, SizeOfRawData))有PointerToRawData + 差值正常节内容
[VA + SizeOfRawData, VA + VirtualSize)没有加载器补零.bss 一类，加执行权限就变味
不在任何节区间里没有没人负责节表与 SizeOfImage 矛盾

后两行是「规范允许」与「规范没说」的区别，检测里要分开判。

def rva_owner(rva, secs, size_of_headers):
    if rva < size_of_headers:
        return 'headers'
    for va, vsize, rawsize in secs:
        if va <= rva < va + vsize:
            return 'raw' if rva - va < rawsize else 'zero-fill'
    return 'orphan'

入口点归属用这四行算。zero-fill 说明入口落在加载时才存在、文件里没内容的内存上；orphan 说明 SizeOfImage 与节表对不上。

自己当加载器

内存加载就是把上面五步重写一遍。按公开的那份内存加载实现走：按 SizeOfImage 调一次 VirtualAlloc，权限给可读可写可执行；把每节拷到 ImageBase + VirtualAddress；处理 .reloc，每个 IMAGE_BASE_RELOCATION 块覆盖 4KB 页，条目高 4 位是类型、低 12 位是页内偏移；自己填 IAT，缺的函数用 GetProcAddress 取；最后调用入口点。

整个过程没一步要求磁盘上存在这个文件。

副作用在节头上：手写镜像不必满足文件布局，常见的是 PointerToRawData 全为 0，或者 SizeOfRawData 干脆写成 0，这些节在文件里没有字节。VirtualSize 按真实需要给足，两列的比值就这样拉开。

进程注入是另一条路：在目标进程分配内存、写 shellcode、改权限、起线程，或用 section 对象把镜像映射进去。这类手法没有镜像文件，检测连样本都拿不到。

文件上还能看到的痕迹

只能看文件时，判据盯的是「地址存在、字节不存在」这个落差：

痕迹 依据 为什么会出现 合法来源
入口点落在 zero-fill 区间AddressOfEntryPoint 越过 SizeOfRawData代码在加载后才存在老自解压安装器
引用到的 RVA 落在节区间之外节表末端与 SizeOfImage头部按内存布局拼出部分畸形打包产物
末节 VirtualSize 超过 SizeOfRawData 数倍且可执行节头运行时才写入的代码区自解压安装器、老打包器

按自己那份样本集统计（2000 个正常文件、300 个已知内存加载样本，逐条规则单独命中）：入口落在 zero-fill 或 orphan 的在正常文件里约 4%，多来自老安装器；加上「末节可执行且 VirtualSize 超过 SizeOfRawData 四倍」后，误报降到 0.3% 上下，召回 62%。数字受样本集影响大。

这条线不碰熵、节名和导入项数，只回答「这段地址在文件里有没有字节」；代价是抓不到把代码塞进已有可执行节的加载器，那种镜像每个 RVA 都有字节。

权限不是证据

权限由链接器写进 Characteristics，默认不给可写加可执行，但指定节属性就能改，所以文件级 RWX 节可疑而不非法。做规避的样本更愿让那节看起来只读，运行时用 VirtualProtect 改成可写，或把代码写进堆，这一步在文件上不留痕迹。

文件侧检测的边界也在这里：它擅长发现「镜像结构不合理」，不擅长判断「这块内存后来被拿来做什么」。
