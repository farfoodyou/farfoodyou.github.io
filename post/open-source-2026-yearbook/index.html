2026 开源年表：从 744B 到 2.8T，从 128K 到 1M

把今年的开源旗舰按时间摆开，趋势比任何单篇评测都清楚。

头部参数一年涨了 3.8 倍（744B → 2.8T），但激活参数几乎没动（40B → 42～49B，Qwen3.8 的 95B 是例外）。这说明：

2026 年的规模增长几乎全部用于“知识容量”，而不是“每 token 算力”。

工程含义：显存需求暴涨（1.6TB 权重），算力需求基本持平（每 token 仍约 40GB 权重读取）。这是对内存容量厂商的利好，对算力厂商的中性。

上下文：1M 从卖点变成入场券

2025 年底开源的旗舰普遍还是 128K 上下文、35KB/token 的 MLA KV。2026 年第一梯队的默认值直接跳到 1M：

时间 模型 上下文 实现
2026-06GLM-5.21MDSA + IndexShare
2026-07Kimi K31MKDA 线性状态
2026-08DeepSeek-V41MCSA + HCA（27% FLOPs / 10% KV）
2026-08Hy41MGated DSA + IndexCache
2026-09V4.1-Flash1MCSA2 + FP4 KV（890 B/token）

一年之内，“1M”从“能塞”进化到“能算得起”：KV 从 35KB/token 压到 890B/token，约 40 倍。

协议：从统一的 MIT 开始分化

类型 模型 企业影响
MIT / Apache 2.0DeepSeek V4、GLM-5.2、LongCat-2.0、Hy4、Mistral可商用、可再分发
Modified MITKimi K2.6需署名，通常可接受
自定义（K3、MiniMax Community）Kimi K3、MiniMax-M3需逐条评估

开源不等于免费商用，这一年在旗舰模型上表现得尤其明显。

结构：四件套收敛

2026 年所有开源旗舰的结构几乎一样：

  1. 细粒度 MoE（256 专家、top-8、1 个共享专家）；
  2. 稀疏/混合注意力（DSA / CSA / MSA / KDA 任选）；
  3. 索引复用（IndexShare / IndexCache / 分层候选池）；
  4. 内置 MTP（投机解码，接受长度提升 10%～20%）。

差异已经不在结构，而在数据管线、RL 配方、以及 kernel 质量。

明年这张表能验证的三件事

  • 3T 有没有人真的部署：如果到 2027 年 6 月还没有开源模型跨过 3T 并公布单 token 推理成本，这条线就停在示范阶段。
  • KV 能不能再压一个量级：890 B/token 往下走要同时动层数、通道和位宽，若 2027 年仍停在百字节量级，说明 FP4 之后没有新手段。
  • 许可证分化会不会影响采用：如果 Modified MIT 和自定义协议的旗舰在公开评测里的出场频率掉一半，说明采购端不买“开放权重”这个说法。

三条都能被明年的公开数据否掉，写在这里当个记录。
