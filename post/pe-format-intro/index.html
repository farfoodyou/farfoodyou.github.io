PE 解析入门：头、节表、导入表里三个容易读错的字段

2022-09-15·6 分钟·2471 字 安全

目录

当天上午九点零五分，告警率曲线几乎是竖直上去的。文件检测引擎的日报里，可疑文件占比从千分之七涨到 11%，样本全是同一批安装包：打包器生成的安装程序、驱动安装包、几个更新包。前一天还是干净的。

最初最容易误判成规则写错。规则当天只调了三个特征的权重，解析代码一行没动：出问题的是特征值本身，那些值从两年前上线起就是错的，只是权重低，从没越过阈值。

时间线

08:40 规则包上线，只改了一件事：把「节熵」「导入函数数」「节数量」的权重从 0.15 提到 0.55。

09:05 告警量涨到日常 15 倍，当天处理的 1.2 万个文件里 1300 个超阈值。

09:20 人工看 40 条告警，全是脚本式打包器和老式快速开发工具链生成的安装包，无一可疑；共同点是末节又大又压缩过。

09:35 回滚，09:50 完成，告警率回到 0.6%。

10:10 开始查为什么这些文件在旧权重下安静了两年。

定位慢在半路上：规则和解析在两个仓。按「阈值太松」查了两小时没进展，最后把样本在解析器里单跑、打出特征值，才看到节熵全在 7.9 以上。压缩过的安装器节熵高正常，不正常的是它两年前就该是 7.9。

三个字段，三种读错

把特征值和解析库的字段逐项对一遍，三处读法都错：

特征 常见读法 正确的读法 对这批文件的后果
节熵取整段 SizeOfRawData 的字节算香农熵只取 min(VirtualSize, SizeOfRawData)，从 PointerToRawData 起读末节含大量对齐填充，熵被稀释
导入函数数只遍历第一个 IMAGE_IMPORT_DESCRIPTOR一直走到 Name == 0 的终止项多 DLL 的安装器只数到第一段的十几个函数
节数量直接信 NumberOfSections先用 SizeOfHeaders 校验节表没越界，再决定是否采信少数样本填 0 或超大值，特征完全失真

三个错误同源：把「文件里的字节」和「加载后的虚拟布局」当成了同一个坐标系。VirtualAddress / VirtualSize 是内存视角，PointerToRawData / SizeOfRawData 是文件视角，只在「这一节确实有原始数据」时才对得上。对齐粒度也不同，SectionAlignment 通常 0x1000，FileAlignment 通常 0x200。

值得当特征的字段

把整个头过一遍，能进特征的不多。

DOS 头只有 e_lfanew 有用，是 PE 头在文件里的偏移。取出来先做范围校验，改过头的样本常在这里露馅。

COFF 头里 Machine、NumberOfSections、Characteristics 区分度不错；SizeOfOptionalHeader 要和 Magic 对上，PE32 是 0xE0、PE32+ 是 0xF0，对不上说明头被改过。

可选头信息最密：AddressOfEntryPoint、ImageBase、SectionAlignment、SizeOfImage、SizeOfHeaders、Subsystem、DllCharacteristics，再往后是 16 项数据目录。SizeOfImage 与「末节虚拟末端对齐后」的值对不上，是加壳的常见副作用。

节表每项 40 字节，节名占 8 字节且不一定以 0 结尾，见过用满 8 字符的节名被截成另一个字符串，拿它做特征会把两个节混成一个。该用的是 Characteristics 的位：MEM_EXECUTE、MEM_WRITE、CNT_CODE。

def section_span(sec):
    raw = sec.SizeOfRawData if sec.PointerToRawData else 0
    virt = sec.Misc_VirtualSize or raw    # 有的链接器把 VirtualSize 留 0
    return min(raw, virt), virt           # 文件字节数 / 内存字节数

def walk_imports(pe):
    # 描述符数组没有长度字段，只能靠全零项终止
    out = []
    for d in getattr(pe, 'DIRECTORY_ENTRY_IMPORT', []):
        for imp in d.imports:
            # 序号导入没有名字，丢掉它等于丢掉一个信号
            out.append(imp.name.decode() if imp.name else '#%d' % imp.ordinal)
    return out

两处细节都是后补的：VirtualSize 为 0 时退回 SizeOfRawData。

改了什么

解析层有了黄金集：300 个真实文件，安装器、加壳、命令行工具、托管程序各 75 个，期望值写死在测试里，口径改动先过硬性比对。

特征定义进了版本号。改口径等于改模型输入，调权前必须重新打分，不能再按「解析代码没动」推断不用回归。

加了不变量检查，结果本身也当特征：节区间不重叠、PointerToRawData + SizeOfRawData 不超文件长度、入口点落在带 MEM_EXECUTE 的节内、SizeOfHeaders 覆盖到节表末尾。规则上线走影子模式，只打分不告警，和线上差异率超 3% 就拦下人工看。

回滚 15 分钟，误报 1300 个文件。贵的是那两年：错的特征在低权重下不报错，只让模型学到稳定偏置。
