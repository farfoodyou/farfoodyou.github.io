Qwen3：把 thinking 开关做进开源权重

4 月 29 日，阿里放出 Qwen3 全系列：两款 MoE（30B-A3B、235B-A22B）+ 六款 dense（0.6B / 1.7B / 4B / 8B / 14B / 32B），全部 Apache 2.0。一次放八个尺寸，本身就是策略：从手机端到机房，一套谱系全覆盖。

但真正值得写的是接口设计。

混合思考：一个权重，两种行为

Qwen3 的卖点是 “seamless switching between thinking mode and non-thinking mode within a single model”（模型卡）。落地形态有三种：

# 1) switch at inference time (transformers / vLLM)
text = tokenizer.apply_chat_template(msgs, tokenize=False, enable_thinking=False)
#                                                     ^^^^^^^^^^^^^ default True

# 2) soft switch inside the prompt
"/think     explain why this deadlock happens"
"/no_think  translate the paragraph above"

# 3) cap the thinking length with a budget (later releases)

对使用者来说，这是同一个模型、同一份权重，只换一个开关。和 Claude 3.7 的 budget_tokens、o3-mini 的 reasoning_effort 是同一思路——但 Qwen3 是第一个把这套接口开进权重里的。

这带来的实际好处很直接：

场景 模式 理由
高并发分类、抽取no-think延迟敏感，答案不需要推理链
数学/代码/多步规划think正确率优先
长文档问答think需要跨段推理
端侧（0.6B/1.7B）no-think 为主算力和功耗受限

训练上怎么做出“两种模式”

公开信息（模型卡 + 后续技术报告）透露的思路是“四阶段后训练”：

  1. 长 CoT 冷启动：先用少量高质量长推理数据把“会想”教会；
  2. 推理 RL：在可验证任务上用规则奖励强化（数学、代码、逻辑）；
  3. 思考模式融合：把长 CoT 能力压缩进短回答，用 DPO/蒸馏让模型学会“该想的时候想”；
  4. 通用 RL：补对话、指令跟随、多语言、agent 能力，防止变成做题机器。

难点在第 3 步：同一份权重里同时存在两种行为模式，推理时必须靠 prompt 或参数显式激活。这本质上是一个隐式的“模式选择器”，训练数据里必须明确标注模式，否则模型会摇摆（该想的时候不想、不该想的时候啰嗦）。

规格与现实的落差

几个容易被忽略的细节：

  • 原生上下文 32K，YaRN 外推到 131K。不是原生 128K，长文场景要靠位置编码外推，效果随长度衰减。
  • MoE 的激活参数是 22B（235B 总参数），单卡部署仍然不现实（fp8 也要 3 张 H100 级），真正好落地的反而是 8B/14B dense。
  • Apache 2.0 是真的宽松，没有“月活超过 7 亿要单独授权”这类条款，对企业合规友好。
  • 119 种语言（报告口径）是训练数据口径，多语言能力在小尺寸上明显弱于大尺寸，“支持”和“好用”要分开看。

开源侧的竞争格局变了

2025 年 4 月的开源第一梯队大概是三家：DeepSeek（V3-0324 / R1）、Qwen（Qwen3）、Llama（即将发布的 4）。Qwen3 的差异化不在单点最强，而在：

  • 尺寸谱系完整：0.6B 到 235B，同一套后训练配方，选型时不用换“家族”；
  • 接口对齐闭源：thinking 开关、工具调用格式、chat template 都往主流 API 靠；
  • 许可证统一：Apache 2.0 覆盖全系，法务成本最低。

这三点的共同指向是降低迁移成本。模型能力差几分，团队会选“换起来最省事”的那个。

落到工程上，我的判断是这样：

  • “思考开关”会成为开源模型的默认接口，没有这个开关的模型在 2025 年下半年会被当成“只能聊天”。
  • dense 小模型被低估。8B/14B 在 think 模式下能顶很多线上任务，延迟可控、部署简单，比 MoE 更适合“每个业务一个模型”的用法。
  • 32K 原生上下文是短板。YaRN 外推在检索类任务上会掉点，长文场景还是得看原生长上下文模型（Gemini 那一类）。
  • 开源追平的是“可验证能力”，不是“产品能力”。榜单上 Qwen3-235B 能和一线闭源掰手腕，但工具调用的稳定性、指令跟随的细腻度、拒答的边界感，差距还在。
