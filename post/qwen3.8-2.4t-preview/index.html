Qwen3.8：2.4T/95B 的旗舰，和一条 27B 的后路

7 月 19 日，阿里放出 Qwen3.8-Max 的预览（官方博客 系列持续更新）。按公开记录，Qwen3.8 有 2.4T 总参数 / 95B 激活，并在 8 月放出 2.4T 与 27B 两档权重（版本记录）。

一面 2.4T，一面 27B——这个组合本身就是策略。

2.4T/95B：稀疏度 4%

指标 数值 对比
总参数2.4TKimi K3 2.8T、V4-Pro 1.6T
激活95B约为总参数的 4%
定位旗舰（闭源 API + 后期开权重）—

95B 激活意味着单 token 算力约等于一个 95B dense 模型：H200 上读 95GB ≈ 20 ms/token，单流上限 50 token/s。这已经是“离线/异步”的量级，不是交互式聊天能接受的。

对这类模型的工程期望应该是：

  • 高价值离线任务（一次性长报告、复杂重构、大规模审阅）；
  • 多机集群（≥16 卡），靠 batch 摊薄；
  • 不指望单流低延迟。

27B：真正会被部署的那一档

历史经验很一致：同一个家族里，能被广泛部署的永远是 7B～32B 那一档（Qwen 系列从 2.5 到 3.x 都是如此）。

27B 的价值在于：

  1. 单机 2 卡（FP8 约 27GB），甚至单卡可跑（INT4）；
  2. 在“可接受”的质量上，覆盖 80% 的线上任务；
  3. 与旗舰共享 tokenizer/chat template，迁移成本低——可以先小后大。

2026 年的通用架构是“双模型路由”：27B 打底，难题升级到 2.4T（或直接用别家闭源）。这比“全用旗舰”省 10～30 倍成本。

一个常见的误判：拿 2.4T 的榜单分数去给 27B 做预期。同一家族的差距通常有 10～20 分，能力是不可“按比例缩放”的。

开源旗舰的“两段式发布”

Qwen3.8 的发布节奏值得记：先闭源 API 预览，再放权重。2026 年这几乎成了标配：

阶段 目的
API 预览收集真实流量反馈、压推理成本
权重发布建立生态、影响私有化采购
小尺寸跟进让上下游用起来，形成事实标准

对使用者的启示：别在预览期就写死选型，等权重和小尺寸都到位再定架构。

落到工程上，我的判断是这样：

  • 2T 级旗舰 + 20～30B 主力，会成为开源阵营的标准双档结构。
  • 稀疏度 4% 附近是最稳的工程点（再稀路由退化，再稠成本上升）。
  • “可部署性”是 2026 年真正的竞争维度，能不能在 1～2 张卡上跑到“够用”，比榜单多 2 分更重要。
  • 如果你自己部署：先上 27B，用真实流量标出难题比例，再决定要不要接旗舰。
