对账：资金系统的最后一道兜底

2021-11-09·6 分钟·2498 字 数据

第一版对账脚本是我写的，两百行，只比当天的总笔数和总金额。某天两边差一笔 0.2 元，按阈值放过；两周后同类差异滚成三百多笔，三个人查了两天，定位到一条回调重放路径在特定重试序列下多记一笔。

教训跟 SQL 无关。总量对账能说「有事」，说不了「哪一笔」，而资金系统里能自动处置的动作都落在单号上。

四条判据

  1. 覆盖哪种单边账。一边有一边没有最贵，金额或状态不一致次之。
  2. 定位精度。总量级等于没有定位，分段级能缩到几千笔，只有单号级才能自动处置。
  3. 一轮的耗时和资源。决定能不能一天多轮、能不能盘中发现。
  4. 差异能否自动处置。不能自动化的方案，差异全堆到人身上。

第 2 条最容易被忽略：平时不花钱，出事时最花钱。

三个方案并排

维度 总量对账 明细差集 分段校验和
能发现总额不一致全部类型全部类型
定位精度无单号分段（万笔级）再下钻
单轮耗时秒级十二分钟量级四十秒量级
资源两次聚合两张全量表排序外连接两次分段聚合
自动处置不可能可以可以
主要成本人磁盘 IO 与副本分段键两边一致

耗时是实测口径：日成功流水 4000 万笔，明细差集单机 8 核跑 12 分钟，这期间两张表都在写，只能落只读副本。分段校验和同样数据量 40 秒。

分段方案只有一个坑，很致命：两边的分段键必须算出同一套结果。自增主键不行，两边 id 空间不同；按单号哈希取模，段号才是同一套坐标系。按文件行号分段的，第一次跨系统就废。

WITH l AS (
  SELECT ('x' || substr(md5(no), 1, 4))::bit(16)::int % 4096 AS seg,
         count(*) AS n, sum(amount) AS amt
    FROM local_bill WHERE biz_day = :d GROUP BY 1
), c AS (
  SELECT ('x' || substr(md5(no), 1, 4))::bit(16)::int % 4096 AS seg,
         count(*) AS n, sum(amount) AS amt
    FROM channel_bill WHERE biz_day = :d GROUP BY 1
)
SELECT COALESCE(l.seg, c.seg) AS seg, l.n, c.n, l.amt, c.amt
  FROM l FULL JOIN c USING (seg)
 WHERE l.n IS DISTINCT FROM c.n
    OR l.amt IS DISTINCT FROM c.amt
 ORDER BY 1;

用 IS DISTINCT FROM 而不是 <>：某段可能只在一侧存在，NULL <> 3 得 NULL，会被 WHERE 过滤掉，最该报警的差异恰好漏掉。

三层漏斗，不是二选一

落地成三层漏斗：总量每十分钟一轮，只比笔数和金额，不一致就置标志位；分段校验和放 T+1 凌晨，把当日切 4096 段聚合比对，就是上面那段 SQL；明细差集只对异常段跑，用 EXCEPT 双向取差。三层跑完出一份差异清单，每行都要带差异码，没归因的差异等于没查。

差异分类决定能不能自动冲正

差异类型 判定依据 处置 执行
渠道有、本地无有渠道流水号，本地无单补账，重放原回调自动
本地有、渠道无本地入账，渠道文件无此单挂账，禁止冲正人工
金额不一致单号匹配，金额差多为部分退款或手续费口径人工
重复入账同单号多条成功流水留最早一条，其余冲正自动

第二行不允许自动，因为信息不足。本地有渠道没有，可能是渠道文件漏传（冲正等于把自己的账抹掉），也可能是本地重复记账（必须冲正），拿到补充文件之前分辨不出来。

冲正本身有三条硬规则：

  • 只追加，不改原流水。冲正写一条反向流水，唯一键是「原单号 + 原因码」，重复执行被挡住。
  • 冲正必须排在原流水之后。用单调入账序号，不用应用层时间：两台机器差几秒就能让冲正排到前面，余额被算成负数。
  • 只处理已确认的差异。确认靠差异码加人工复核或渠道补文件，对账系统不猜。

容忍阈值分三档

拍一个总数当阈值是错的，不同差异码的基线差几个数量级。重复通知类的基线在千分之零点三上下（口径：三个月日均值，含活动日），属于噪音；单边账基线是 0，出一笔就值得看。

所以按差异码分别设三档：

档位 口径 动作
条数单差异码笔数 > 50停该类自动冲正，告警
金额单笔 > 100 元，或日累计差 > 当日成功金额 × 2e-5立即告警，人工介入
结构某差异码占比 > 30%，或连续三天同码判定系统性问题，停对账并排查

三档是「或」的关系，任一触发就升级。第三档后来才加，比金额管用：手续费四舍五入方向不一致这类差异，一天几百笔、一笔两分钱，金额拦不住，占比会立刻暴露。

阈值钉在配置里，改动要两人确认并记下前值。这条流程拦下过一次事故：有人为消掉告警把金额阈值调大一个数量级。

对账的价值不在对上多少，在于给出差异时人能多快决定怎么处置。能定位到单号、带差异码、分档告警的清单才算把兜底做完；只比总额的脚本给的是心理安慰。
