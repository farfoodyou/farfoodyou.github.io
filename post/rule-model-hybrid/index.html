规则、模型、再一层规则：一晚漏检换来的编排顺序

2023-09-05·6 分钟·2485 字 安全

七月的一个周五，凌晨两点，值班侧在看板上来回切时间窗。一个家族的检出量从傍晚开始一路下滑，到零点只剩原来的七成，跟灰度比例对得上。而所有单点指标都是绿的：前置规则的命中率在正常区间，模型打分的分布没有偏移，队列没积压，错误率没动。

问题出在终点。同一批文件，模型给了 0.93，标签也对，最后写进结果的 verdict 是 clean。从哪一步开始掉头的，日志里没有一行是「错」的。

链路上有三段：前置规则做快筛和黑白名单，模型打分并给出家族标签，后置规则拿到分数和标签做策略裁决——抑制、升级、附加处置。前两段各自工作正常，第三段按标签字符串精确匹配。那天模型换了标签命名法，后置规则一条都没匹配上，落进了「无匹配则放行」的默认分支。

那一晚的时间线

时刻 发生了什么
20:10模型新版本开始在 30% 的机器上灰度，标签从家族名改成「家族名+变种序号」
22:40值班发现该家族的检出量掉了三成，先怀疑上游没送样本
23:05抽单机日志，score 与标签都在，verdict 是 clean，开始怀疑后置策略
23:30打印后置规则的匹配轨迹，命中数为 0，确认标签不匹配
00:20回滚模型版本，检出在 12 分钟内回到基线
01:10起补扫任务，把 20:10 之后入库的文件重跑一遍

中间那一个多小时花在排除「样本没进来」和「模型没跑」上，两件事都有监控，排除得快。耗时间的是最后一段没有监控，没人记录「这条规则今天一次都没命中」。规则空转是静默的。

从 score 到 verdict

后置策略的原始写法是这样，每条策略一个条件，条件全部满足就执行动作，都不满足就走默认分支：

type Policy struct {
    MatchTag  string   // 精确匹配模型输出的标签
    MinScore  float64
    Action    Action   // Suppress / Escalate / Tag
}

func (e *Engine) Post(r Result) Verdict {
    for _, p := range e.policies {
        if p.MatchTag == r.Tag && r.Score >= p.MinScore {
            return e.act(p.Action, r)
        }
    }
    return Verdict{Label: "clean", Reason: "no-policy-match"} // 默认放行
}

MatchTag 是字符串相等。模型侧把 family-x 改成 family-x.3，这个等号就永远不成立，1400 多条策略集体失声。这套编排本身没有错，错在两端之间没有契约：模型输出的标签集合是一份隐式协议，规则侧按字符串硬编码依赖它，而两边的发布节奏完全独立。

顺序也有讲究

同一个模型和同一批规则，编排顺序不同，失效模式差很多：

编排 优点 失效表现
规则门禁 → 模型挡掉大部分明显样本，省算力规则一旦过宽，模型看不到那批样本，漏检无痕迹
模型 → 规则裁决模型是主判据，规则只调节规则依赖模型输出格式，格式变则规则静默失效（这次就是）
规则快筛 → 模型 → 规则兜底快筛省成本，兜底能纠正模型的明显错判兜底层的默认方向决定事故性质：放行则漏检，升级则积压

第三种形态只做了一半：兜底层存在，方向反了。默认放行隐含「没匹配上就不需要处置」，这个假设在标签体系变更那天就失效了。

改了什么

默认分支反转。 后置规则匹配不到任何策略时，不再给 clean，而是进复核队列并带上 unmatched-tag 的原因码。代价立刻显出来：升级率从 0.4% 涨到 1.1%，人工队列每天多四十来单。这笔成本换来的是可见性：静默失效变成能报警的积压。

补契约测试。 模型侧声明会输出哪些标签，规则侧声明依赖哪些标签，构建时取交集，差集非空就失败。另外在 CI 里放 2000 份固定样本，断言全链路 verdict 与基线一致，改标签或改阈值都会撞墙。

拆分发布节奏。 规则按天甚至按小时发，模型按周发，两者不再进同一个变更窗口。绑在一起发布，等于让最贵的那次变更加上最高频的风险。

给空转加观测。 每条策略上报命中次数，连续 24 小时为 0 的策略进巡检清单，这次能提前十小时暴露。

兜底该由谁做

规则擅长确定性判据：结构越界、签名命中、字段自相矛盾，这类判断没有概率，错了能指到字节。模型擅长模糊相似：同一个家族改了壳、换了编译选项，规则写不完，模型能认。兜底该落在「确定性能不能认出来」那一层，不该落在分数上。

模型不该做兜底。它一旦成了最后一道，任何输出格式变化都会直接变成线上判定结果，而这类变化在离线评估里看不出来：评估集用的是旧标签，新旧标签名的映射没人维护。

一个还没解决的边界

前置规则过宽导致的漏检，至今没有好的自动发现手段。规则挡住样本之后模型不会跑，下游也没有分数，能看见的只有「这条规则命中量突然涨了十倍」。现在靠周级抽样回放：从被前置规则拦掉的样本里随机抽 0.5%，绕过前置送模型比结论。抽得少，只能发现粗粒度分歧，对「规则写宽了」够用。
