样本分级：118 万份文件该怎么花算力

2023-11-07·6 分钟·2498 字 安全

以一个工作日 118 万份文件的入库量为例（示例口径）：峰值小时占 9%，也就是 29 份每秒。这个数不大，但每种手段都「全量跑一遍」，账立刻不对。把三档算力列成一张表之后，「检测成本高」这种说法就不必讲了，直接报数。

第一页：全量跑各要多少核

日核小时 = 日份数 × 单份核秒 / 3600。单份核秒按单核独占算，不含排队。

手段 单份耗时 日核小时 常驻核数 峰值核数
廉价特征3ms0.980.040.07
模型打分250ms823.47.25
动态沙箱15s4917205435

峰值核数是按峰值小时口径重算的：29 份每秒 × 单份耗时。沙箱那一行说明问题不在平均，在峰值。435 个核的峰值容量，为了每天零点几个百分点的判定需求常驻，账算不过来。

模型那一行倒是意外地便宜：82 核小时一天，峰值 7 个核多一点。所以「分级」这件事的收益分布很不均匀，它省的是沙箱，不是模型。

第二页：廉价特征能砍掉多少

第一级只看不用执行就能拿到的特征：容器能否解析、节表与入口点的关系、字节熵的分段分布、可打印字符比例、导入符号数量、是否含宏或脚本块、字符串的语言字符占比。单份 3ms，其中 2ms 花在解析容器头上。

这一级不需要判断「恶意」，只需要判断「值不值得看」。用两周带标注的样本拟合一个线性模型，输出 0~1 的通过分，分数越高越可疑。阈值 0.70 时，88.4% 的样本直接判为良性，剩 11.6%（约 13.7 万份）进第二级。

容易犯的错：把廉价特征做成小模型去跟大模型比准确率。它比不过，也不需要比，唯一要保证的是「被它放过去的样本里恶意比例低到可接受」。

0.70 这个数是分位点：用 numpy.percentile 在良性样本的分数分布上取 88 分位，比手调稳。分布漂了就重算分位点，不用重新训练。

第三页：阈值是一道选择题

阈值往上抬，漏检少、成本高；往下压，成本低、漏检多。这个取舍得用数说话。

阈值 通过率 进第二级份数 影子外推日均漏检 第二级日核小时
0.6091.0%10.6 万117.4
0.7088.4%13.7 万49.5
0.8082.1%21.1 万1.214.6

「影子外推」：24 小时里所有样本额外跑一遍全量模型，只记录不处置，看被第一级判为良性的那批里模型给高分、人工确认恶意的有多少，再乘上流量周期。

选 0.80：从 0.70 到 0.80，第二级每天多花 5 个核小时，漏检从 4 份降到 1.2 份。再往上抬到 0.9，第二级会涨到 30 万份、22 核小时，漏检只再降 0.4 份，边际收益已经不成立。

顺手把沙箱的入口也定在这一级：第二级分数超过 0.93 才进沙箱，占总量 0.6%，约 7000 份，日耗 29.5 核小时。这条线比第一级更宽松，因为沙箱单份 15 秒，动一格就是几十核小时。

第四页：回退全量要花多少

分级器是省算力的前提，一旦漂了，省下来的就是漏检。三种情况会关掉分级、回退全量：

  • 模型换版本。判据变了，旧的分位点全部作废。
  • 规则大改。第一级里有一半特征来自规则命中的强弱，规则改了，分数分布跟着变。
  • 分布漂移。第一级分数均值偏移超过 2 个标准差，或者一类家族标签的出现率一天内涨 5 倍。

回退不是把流量重新压到 435 核的峰值上，而是分两步：先让第一级只做「明显良性」的粗筛（阈值抬到 0.95，通过率降到约 60%），再把余下的全量送模型；沙箱只在夜间低峰窗口做抽样全量。

夜间 6 小时窗口的全量模型是 82 × 6/24 ≈ 20 核小时，加上沙箱抽样 2%，约 100 核小时。一天一次，可以接受。这个窗口同时也是重新拟合分位点的数据来源：白天用旧阈值撑着，夜里把新分布算出来。

def triage(f, budget):
    s0 = cheap_score(f)                    # 3ms，全量
    if T0 > s0:                            # T0 = 0.80
        return "clean", 0
    s1 = model_score(f)                    # 250ms
    if T1 > s1:                            # T1 = 0.93
        return "record", 1
    if 15 > budget.left:                   # 沙箱配额，单位核秒
        return "queued-for-night", 2       # 配额用完就排队，不降级判定
    budget.left -= 15
    return sandbox(f), 2

budget 那段不能省。配额打满时，最省事的做法是降级成只记录，但那等于在高峰期悄悄降低判定强度，还没人看得见；排队到夜间窗口至少留一条待办。

账算完剩下的判断

这套分级省下来的大头是沙箱那 4900 核小时，模型那部分从 82 降到 9.5，属于顺带。如果检测链路里没有动态执行，只有规则加模型，那么分级的性价比要重新算一遍：省 72 核小时，代价是两套判据、一次分位点拟合和一条影子链路，很可能不划算。

另一个反直觉的地方：第一级的耗时上限比它的准确率重要。3ms 能全量跑，30ms 就只能抽样，一旦变成抽样，第一级就不再是「筛子」，而是「采样器」，后面所有关于通过率的推导都不成立。所以廉价特征要划一条硬线：单份不超过 5ms，超了就从特征集里删掉，不管它多有区分度。
