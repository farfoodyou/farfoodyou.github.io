沙箱逃逸检测：从日志特征到随机森林

2022-11-30·6 分钟·2483 字 安全

SECCOMP_RET_TRACE 让匹配到的系统调用先不执行，把控制权交给 tracer，处理完再让内核继续，出口处再停一次。这个“两次停”决定了两件事：日志天然成对，以及后面能算出什么特征。

我做的事是把成对事件变成一张树模型能吃的表；坑的位置由内核接口语义决定，跟模型选型无关。

从寄存器到一行记录

入口读 orig_rax 与六个参数寄存器（rdi / rsi / rdx / r10 / r8 / r9），出口读 rax 取返回值。

参数里的指针指向被测进程的地址空间，取值要用 process_vm_readv；读失败是常态（映射被改、地址是编的、页被换出去），记空值不重试，重试等于把停顿时间交给对方控制。

调用号架构相关，同一个 openat 在两种主流架构上编号不同，宿主又是混布的，采集侧做归一化表，模型只看内部 id。

最要命的是 openat 第二个参数：那是用户态的字符串，不是内核最后打开的对象。换成对象要 dirfd 加当前 cwd，而两者都会变，符号链接也会指向别处。所以入口读出的字符串只用于结构特征，“打开了哪个文件”一律等出口返回值加一次 readlink(/proc/<pid>/fd/<n>)。

RESOLVE_BENEATH 那一维我最早判错了：它让内核把路径解析限制在 dirfd 之下，越界的 .. 直接返回 EXDEV，方向与逃逸相反，正常软件里也少见；它的用处是反向判据——出现它更可能是良性组件。

特征只取结构

字面量特征离线漂亮、上线就崩：改一个码位就换一族特征，同族样本还会跨训练集与验证集泄漏。412 维里没有一维是原始字符串。

特征组 具体量 单特征 PR-AUC
文件越界挂载点外操作占比、失败率、目标目录基数0.19
序列 n-gram归一化调用号的 3-gram 哈希到 2^14 桶0.16
特权调用mount、unshare、ptrace、io_uring_setup0.11
反分析读 /proc/self/status、cpuid 频率0.12

（口径：1400 正样本、400 万负窗口，按族分组 5 折，取折均值。）

单看哪组都不够，合起来 0.56。越界文件操作说明“想往沙箱外落东西”，特权调用说明“在找内核面”，反分析说明“知道自己被看着”，三者同时出现才构成逃逸的形状。组合由树自己找，不必手写 A and B and not C。

序列：窗口 30 秒，从样本启动算起；先去噪（futex / epoll_wait / clock_gettime），剩下调用号做 3-gram 哈希到固定宽度。牺牲长程依赖换维度可控。

1:2800

正样本 1400 个：历史人工确认的逃逸尝试，加按内核接口构造的样本（主动碰 core_pattern、无 CAP_SYS_ADMIN 时 mount）。负样本 400 万窗口。

  • 不做 SMOTE。 离散特征上插值会造出“半开 openat2 且半个 ptrace”这种不可能窗口，模型学到的是插值器的偏差。
  • 训练时降到 1:10，但挑着降。 随机降采样会筛掉打包器、安装器、编译器，而这些正是误报主要来源；按特征距离保留难负样本。
  • 只看 PR 曲线。 1:2800 下 ROC-AUC 0.99 毫无信息：假阳率从 0.1% 到 1%，ROC 上看不出，人工队列却从 8 条变成 8000 条。

划分按“样本族”分组而非按样本：同族变体跨两侧时 PR-AUC 虚高 0.1 以上。我第一次跑就踩了，查两天才发现泄漏。

阈值按告警预算定

clf = RandomForestClassifier(
    n_estimators=400, max_depth=12, min_samples_leaf=5, n_jobs=8,
    max_features=0.3, class_weight='balanced_subsample', random_state=7)

def pick_threshold(scores, budget):          # 夹到 [0.40, 0.90]
    q = 1.0 - float(budget) / max(len(scores), 1)
    return float(np.clip(np.quantile(scores, q), 0.40, 0.90))

概率值不能跨天比：森林输出是叶子投票比例，分布一漂，0.83 的排名可能完全不同。固定的是“每天进人工队列的条数”——沙箱每天四万窗口，复核侧能吃下 6 到 9 条，就按这个预算算分位数。

夹逼防两种退化：0.90 防止分数整体偏高时没人能过，0.40 防止塌下去时放进几千条。入队条数偏离预算两倍以上就告警，不自动调阈值；跟着分布跑等于把漂移藏起来。再加“同一样本只出最高分窗口”，队列重复率从三成降到不足一成。

上线首月（口径：30 天，仅该模型推入）：41 条确认为逃逸尝试，9 条是同批重复；已知 14 起事件命中 11 起。漏掉的 3 起是同一类：进程在窗口开启前就完成探测，日志里只剩无害尾部。调阈值解决不了，只能改窗口起点。
