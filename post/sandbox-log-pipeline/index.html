沙箱日志的结构化与压缩：一份报告 9MB 的账

2023-05-23·6 分钟·2239 字 工程

每天 35 万份沙箱报告，平均每份 9.0MB，落盘 30 天的原始体积是 94.5TB。这个数决定了后面每一个设计选择，所以我把它写在管道文档的第一行，任何人改 schema 或改保留期，先对着它算一遍。

35e4 份/天 × 9.0 MB = 3.15 TB/天
3.15 TB × 30 天     = 94.5 TB

先看 9MB 里面是什么

一份报告平均 4.2 万条事件，摊下来每条 214 字节。事件分三类：进程创建、文件操作、网络连接。膨胀的原因不在事件数量，在重复：同一份报告里同一个文件路径平均出现 310 次，一次进程树展开能把同一个系统目录下的路径重复写上几千遍。

按字段实测，78% 的字节是字符串，其中绝大多数是重复的路径、命令行前缀、注册表键。剩下的 22% 里，时间戳和 ID 占掉了八分之一。

所以第一刀不砍事件，砍表示方式。

一行一事件，字符串进表

结构改成窄表加字符串表：时间戳存相对报告起点的毫秒差（varint），路径和命令行换成整数 ID，事件类型用短枚举，参数放变长列。

{"r":"7f3a","t":412,"k":3,"pp":1180,"p":1204,"op":"CreateFile","a":{"path":9321,"access":3,"size":4096}}

r 是报告 ID，t 是相对毫秒，k 是事件类型，pp 和 p 是父进程和进程 ID，a 是参数映射。字符串表单独一份，按报告存增量字典，路径 ID 在报告内有效。

结构本身用二进制编码，不保留 JSON 的键名重复，CBOR 的规范里有现成的类型标记可以借。每行落到 28 字节，4.2 万行是 1.18MB。

4.2e4 行 × 28 B = 1.18 MB/份
35e4 × 1.18 MB  = 413 GB/天 → 30 天 12.4 TB

体积降到原来的 13%，但查询还是慢，因为行存下按事件类型过滤要读全行。

列存加压缩，再算一遍

按列切分，每列独立压缩。zstd 级别 3，用 1 万份历史报告训练一份字典，路径、命令行这类字符串列的压缩比能到 12 比 1，数值列只有 3 比 1 左右，加权下来整份 0.18MB。

35e4 × 0.18 MB = 63 GB/天 → 30 天 1.89 TB

从 9.0MB 到 0.18MB 是 50 比 1，其中约 7 倍来自结构化，其余来自压缩。这个顺序不能反：直接对原始 JSON 压，只有 6 比 1，因为压缩器处理不了跨行的重复结构，而结构化把重复显式变成了整数 ID。

采样率是倒推出来的

查询只关心三件事：单条规则最近命中了什么、一类家族的样本长什么样、一个时间段的整体分布。这三件事对精度的要求不同，所以采样不按统一比例做。

  • 命中检测结果的样本（约 4%）全留，它们要用于证据链和申诉复核；
  • 沙箱崩溃或超时的样本（约 1%）全留，异常本身是信号；
  • 其余按 8% 随机采样，用哈希取模，保证同一份样本每次判定一致。
def keep(row):
    if row["hit"] or row["crashed"]:
        return True                      # 结论相关的全留
    return crc32(row["sha256"]) % 100 < 8

保留率 12%，落盘 7.6GB/天，30 天 227GB。

阶段 单份体积 日增 30 天 单查询扫描量
原始 JSON9.0 MB3.15 TB94.5 TB5.9 TB，扫不动
结构化1.18 MB413 GB12.4 TB775 GB
加列存压缩0.18 MB63 GB1.89 TB118 GB
加采样 12%0.022 MB7.6 GB227 GB14.2 GB，约 6 秒

单查询扫描量按「48 列里取 3 列」估的，压缩列存能跳掉不读的列，所以是 30 天数据量乘以 3/48。单节点扫描吞吐按 2.4GB/s 算，6 秒这个量级对交互式检索刚好够用。

采样丢掉的东西怎么补

12% 的采样对「看趋势」够用，对「精确计数」不够。一条命中率 0.5% 的规则每天命中 1750 份，采样后剩 210 份，看日环比够，按家族拆开就不够了。

补的办法是在结构化阶段顺手物化一张小表：按规则 ID、家族、小时三个维度聚合命中计数，不做采样，全量累加。这张表每天 300 万行、约 12MB，精确统计全走它，采样数据只用来取原始事件。

边界

schema 演进用类型枚举加分派，新事件类型直接加一种 k，读取端不认识就跳过，不做全表迁移。30 天滚动窗口让旧格式自然淘汰。

采样率按天算，不按小时算。工作日和周末的流量差三倍，如果在低峰时段提高采样率，样本的时间分布会失真，而攻击流量恰好有明显的时段偏好。

压缩字典每季度重训一次。旧数据必须留着旧字典，帧格式里带字典标识，所以解码时按标识加载，zstd 的帧规范把这块定义得很死，换字典不会影响历史数据可读性。
