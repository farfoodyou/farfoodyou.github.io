小显存的极限：125B 跑在 12GB 显卡上，账是怎么算的

125B 跑在 12GB 卡上不是魔术，是把“权重放哪”重新排了一遍。 显存不再是容器的下限，带宽才是速度的上限。下面四份实测里，12GB 是官方下限，10GB 是再往下压一档的调优结果。

三份公开实测：

引擎 硬件 模型 关键数字
Strata（官方基线）1× RTX 5070 12GB + 64GB DDR5Qwen3.8-Flash-Next 125B（Q2_0）decode 94 tok/s，prefill 2650 tok/s；IQ3_S 53 / 1620（128K 上下文）
Speedy（Strata 的非官方调优分支）1× RTX 3080 10GB + 128GB DDR4同上（Q2_0）decode 152 tok/s，200K prefill 2562 tok/s，冷读 200K 78s
NInfer1× DGX Spark（128GB 统一内存）Qwen3.8-Flash-NextMTP3：70 tok/s @C=1，328 tok/s @C=16
NInfer2× DGX Spark（200Gb/s RDMA，TP2）同上109.5 tok/s @C=1，811.9 tok/s @C=32

两行消费卡的区别值得先说清：Strata 官方要求 12GB 显存起（RTX 20/30/40/50 系或对应 AMD 卡），发布数字全部在 RTX 5070 12GB 上测；Speedy 是第三方针对 10GB 3080 重调 preset 的分支，10GB 低于官方下限，属于把每档余量都榨干的做法。两行摆在一起，正好看出显存少 2GB 要付多少速度和工程成本。

对照组：同一台机器上 NInfer 跑 27B 稠密模型（RTX 5090，权重 15.9 GiB），decode 84 tok/s、prefill 3300 tok/s。125B 的 MoE 在小显存机器上比 27B 稠密还快，这件事值得拆开看。

为什么 125B 能进 12GB

Qwen3.8-Flash-Next 的参数量拆得很特别（模型卡）：

125B  主模型（每 token 激活 6B）
 51B  n-gram embedding（二元/三元组查表）
  4B  MTP（投机解码头）

三块东西的访问模式完全不同：

部分 大小 访问方式 放哪
注意力 + 共享层 + 激活专家6B 量级每 token 必读显存（热）
其余专家（125B - 6B，119B）≈ 36 GB（Q2，2.4 bit/参数）按路由稀疏访问内存（冷）
n-gram embedding51B按 token 查表，极少命中磁盘/内存
MTP 头4B每次投机解码显存

n-gram embedding 是这代架构最“取巧”的设计：它用查表代替矩阵乘，参数量可以很大而算力几乎为零，且天然适合 offload——命中就取一行，不命中就跳过。官方措辞是“更易于 offload 而非 MoE”，说的就是这个。

于是 12GB 显存只需要装“每 token 必读的 6B”，剩下的按需从内存搬。冷侧的总账也不大：119B 专家按 2.4 bit 算 36GB，51B 查表按同精度算 15GB，合起来约 51GB，正好压进 5070 那台的 64GB DDR5 里。

那 94 / 152 tok/s 是从哪来的

这里必须算带宽，因为 decode 的每一步都在搬权重。

假设 Q2_0 量化约 2.4 bit/参数，激活 6B：

每 token 需读取 ≈ 6B × 2.4/8 ≈ 1.8 GB
94  tok/s  → 需要 ≈ 169 GB/s 的有效带宽   （RTX 5070 12GB，Q2_0）
152 tok/s  → 需要 ≈ 274 GB/s 的有效带宽   （RTX 3080 10GB，Q2_0）

对照硬件：

通路 理论带宽 实际可用
RTX 5070 12GB（GDDR7，192-bit）672 GB/s只够装热专家
RTX 3080 10GB（GDDR6X，320-bit）760 GB/s只够装热专家
DDR5-5600 双通道（5070 那台）89.6 GB/s实测 70 左右
DDR4-3200 8 通道（3080 那台）204.8 GB/s实测约 150～190
PCIe 4.0 x1632 GB/s实测 25 左右

两组需求都超过了各自机器的内存带宽（169 > 89.6，274 > 204.8），所以真实机制只能是“热专家常驻显存 + 冷专家走内存 + 部分走 PCIe”三层混合。两个数都是三层叠加的结果，不是单一路径：3080 那台能把 152 做出来，一半来自更宽的 DDR4 八通道，一半来自解锁后的 prefill 路径。

这也解释了为什么“更多显存 = 更多专家常驻 = 更快”，官方 README 直接给了外推（RTX 3090 24GB 大致 100～140 tok/s），Speedy 那边反而老实写了“more VRAM fits more experts but is unmeasured”，没测过就不敢承诺。两家对同一件事的态度差异，比数字本身更值得看。

三处带宽的账，差一个数量级

容量这一关是可以绕的：显存装不下就量化、冷热分离、丢磁盘，代价是首次加载慢和精度掉一点。真正钉死速度的是 DRAM：当 6B 激活权重都得从内存流式读取时，上限 = 内存带宽 / 每 token 字节数。128GB DDR4 八通道约 200 GB/s，对 1.8GB/token 就是 110 tok/s 量级；12GB 那台的 DDR5 双通道只有约 90 GB/s，同样算法掉到 50 tok/s 量级。实测 94 和 152 都高于这条线，说明热专家缓存确实在起作用，但这个天花板自己抬不动，除非把内存换成十二通道或者统一内存的 LPDDR5x。

再往下是 PCIe：4.0 x16 只有 32 GB/s，比 DRAM 又低一个数量级。一张卡装不下、又没有 NVLink 时，每 token 的跨卡流量都走这条窄路。双 Spark 用 200Gb/s（25 GB/s）RDMA 加 TP2，是在这个约束下换“能跑更大模型”，不是换“能跑更快”。

一个直接对比：

场景 单 token 搬运 有效带宽 上限
5090 跑 27B 稠密（16GB/token）16 GB1.79 TB/s（HBM）~110 tok/s
5070 跑 125B MoE（1.8GB/token，全命中）1.8 GB672 GB/s（HBM）~370 tok/s
3080 跑 125B MoE（1.8GB/token，全命中）1.8 GB760 GB/s（HBM）~420 tok/s
双 Spark 跑 125B（TP2）分摊 + 跨机25 GB/s（RDMA）~110 tok/s

HBM 那两行的 370/420 是“全命中”的理想值，实测 94/152 说明真实命中率远达不到——每少命中一个专家，就多一次内存往返。同一块卡上换个 router 分布偏一点的 prompt，tok/s 能差两三成，这是整套方案里最不稳定的一环。

投机解码在这里格外值钱

上表的“110 tok/s”是每 token 一次前向的上限。投机解码改变的是“每次前向产出几个 token”：

  • NInfer 在单 Spark 上开 MTP3（K=3）做到 70 tok/s @C=1，关掉会更低；
  • Speedy 的 decode 数字全部是“with MTP speculative decoding”（官方那 94 tok/s 同样带投机，关掉后 Q2_0 掉到 60 出头）；
  • 而 acceptance 高的任务（代码、结构化输出）能吃满，开放式写作就打折。

换句话说：当带宽被锁死时，唯一还能涨的杠杆是“一次前向多吐几个 token"。这也是今年所有端侧引擎都在做 MTP/DFlash 的原因；投机的收益边界和退化条件见投机解码的账。

QSA 与 Gated Residual：省的是 prefill

decode 被带宽锁死，prefill 却是算力活。Qwen3.8-Flash-Next 的两个结构改动都冲着长上下文 prefill 去：

  • QSA（Qwen Sparse Attention）：在 micro-block 级别选块而不是选 token，对长序列的注意力计算降一个量级，同时避免 token 级 gather 的低效（token 级稀疏在 GPU 上很难 coalesced，这点见 稀疏注意力横评）。
  • Gated Residual：加宽残差流并用门控读/写，训练更稳、推理开销小。

效果在数字上：单 Spark 冷读 200K 上下文，Speedy 在单张 3080 上要 78 秒、NInfer 在 262K 上限下 TTFT 是几十秒量级。“能塞进 200K”和“能等它读完 200K”是两件事。

这些专用引擎的硬限制

  1. 模型白名单。Strata/NInfer/Speedy 都只支持特定 checkpoint（甚至特定 .ninfer 制品），换个 HuggingFace 权重不一定能跑。通用引擎（vLLM/SGLang）胜在覆盖面。
  2. 量化质量不可忽视。Q2_0 / IQ2_XS 在 125B 上有“参数多掩盖量化损失”的优势，但 IFBench（指令跟随）这类敏感指标仍会掉——Speedy 的 README 就单列了 IFBench。
  3. 许可证是坑。Strata 是 MIT；Speedy 是“个人非商用”；NInfer 的自定义许可对商用要逐条看。能跑 ≠ 能商用。
  4. 并发弱。单机小显存方案的强项是“一个人用”，不是“多租户”。NInfer 单 Spark C=16 时 328 tok/s 已经算好的，但那是在 262K 上下文上限内、且 KV 池占掉 38GiB 的情况下。
  5. 工程门槛高。构建要 sm_120a / sm_121a（5090 / Spark 专属），要 CUDA 13.x、要 gpu-unlock 这类非官方补丁（Speedy 的数字全部在解锁 LHR 后测得，不解锁 prefill 掉 10%～12%）。

什么情况下别玩这套

  • 要通用模型支持：直接 vLLM/SGLang + 官方量化，别折腾白名单引擎。
  • 要多租户/高并发：桌面级方案不是为这个设计的，上数据中心卡。
  • 要商用：先看许可证，很多“能跑 125B”的项目只允许个人使用。
  • 要稳定复现：这类引擎迭代极快（NInfer 两个月内改了多轮 benchmark 方法），版本锁不死就别指望可复现。

想自己复现，先测两个数

拿自己的机器复现这套之前，先量两个数，量完就知道上面哪些数字能搬到你这儿：一是热专家命中率，同一批 20 条真实 prompt 连跑两遍，看 decode 的波动，波动超过 30% 说明 12GB 装不稳那 6B 激活，得把量化再降一档；二是冷读带宽，取一条 200K 上下文的请求，用下载字节数除以 TTFT，64GB DDR5 双通道要测到 70 GB/s 以上才算配置正确，低于这个数就是磁盘或 mmap 路径没调好。这两个数把你定位在“94 tok/s”和“个位数 tok/s”之间的某一格，比任何卡型外推表都准；想知道每一档的配置细节，NInfer 的性能文档把每个 run 的 KV 容量、接受长度都列了出来（performance 目录）。
