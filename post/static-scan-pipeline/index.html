静态扫描流水线：从收到文件到给出判定

2022-07-06·6 分钟·2413 字 安全

选型讨论最容易跑偏的地方是先比方案。三个方案各有拥趸、各有反例，讨论两周也可能没有结论，最后常常卡在一个没人定义的问题上：这引擎到底要在多少毫秒内给出答案。判据没写下来，方案就没法比。

所以先把判据摆在前面。

五条判据，其中两条能否决

判据 阈值 为什么能否决
单文件判定时延同步路径 P95 ≤ 300ms上传即等结果，超过就得改成异步，产品形态全变
判定可解释必须给出规则名与命中偏移客户要来申诉，说不出理由的判定无法运营
冷启动新文件类型不依赖历史样本新格式出现时没有标注数据
嵌套容器压缩包、Office 内嵌、邮件附件要能看到大多数投递都套了一层壳
误报可控单规则误报率 ≤ 0.2%（回归集口径）扣文件这件事，误伤一次的成本远高于放过

后两条是硬否决，前三条可以谈判。判据写完之后，讨论从「哪个方案先进」变成了「哪个方案能过这五条」。

三个方案并排

判据 A 纯规则静态 B 静态特征 + 打分模型 C 动态沙箱
单文件时延50–200ms200ms–1s（上界越线）30–120s
单机吞吐每核每天十万级每核每天万级每核每天千级
可解释规则名 + 偏移，最干净特征贡献度，需要额外说明行为日志，人能读但要归纳
冷启动写规则即可，天级需标注样本，周级无需训练，但要环境适配
嵌套容器解包后逐层判，成本可控同左，特征提取要防炸多数样本跑不到内层
误报可控靠规则精度，易回滚靠阈值，整体可调依赖环境保真度

C 在第一条就被淘汰：30 秒起步的时延没法放进同步上传路径，只能做二级分析。B 也只守住下半段，200ms–1s 的上界同样越线，能留在同步路径上的只有静态特征那一部分，打分模型不能在线等。剩下 A 和 B 的差别在覆盖面上，B 能吃到「一堆单独看都不致命、凑一起很可疑」的文件，A 只能吃到写得出规则的东西。

实际落地是 A 打底、B 补位：所有文件先过 A，A 给出高分直接判；A 给不出结论、类型又可解析的样本才进 B 的静态特征部分，这一段压到 P95 300ms 以内。要跑打分模型或沙箱的样本走异步队列，一天的回溯窗口足够，C 也在这一侧。

类型识别：先看字节，别信扩展名

流水线的第一个动作决定后面所有分支。扩展名来自发送方，只当作一个交叉校验字段：内容判断结果与扩展名不一致，本身就是一条特征（一个 .doc 实际是 PE 文件，权重不低）。

判类型读文件头 8KB 就够，用 magic 之类的字节签名库，比手写 if 稳，也比全量解析便宜。这一步同时决定了「能不能解包」和「该用哪一组规则」。

type_probe:
  read_bytes: 8192
  on_mismatch: record_feature      # 扩展名与内容不一致 -> 记为特征，不拒绝
unpack:
  max_depth: 5
  max_total_bytes: 209715200       # 展开后总量上限 200MB
  max_ratio: 200                   # 压缩比超限按疑似炸弹隔离，不再展开
  recurse_types: [zip, gzip, ole2, ooxml, pdf]
  per_member: true                 # 每个成员重新走类型识别
score:
  threshold_flag: 60
  threshold_block: 80

max_ratio 这条有具体数字支撑：一个 40KB 的压缩包能展开成几个 GB，解包器如果不设总量上限，一次投递就能把扫描节点的磁盘写满，后面的正常文件全部排队。

解包：把爆炸半径关在小盒子里

解包器要当成不可信输入处理，三件事必做：深度上限（嵌套压缩包按层递归，5 层之后一律只记录不展开）、总量上限、单成员大小上限。任何一个超限，判定结果直接写「容器异常」，不再往下走。

每个展开出来的成员要重新走类型识别，不能沿用父容器的结论。Office 文档里嵌一个可执行文件、PDF 里挂一个压缩流，这类结构在投递样本里占比不低，跳过这一步等于白做。

规则：按类型分桶，先便宜后昂贵

规则按文件类型分桶，别全局扫。一堆针对 PE 节的规则拿去扫 PDF，纯属浪费 CPU。

同一个桶内按代价排序执行：字符串与文件大小条件最便宜，正则次之，带循环或偏移计算的最后。命中一条高分规则就可以短路，跳过后续昂贵规则。

分数不是规则权重的简单相加，而是「最高分 + 命中数量的对数加成」，避免一个文件靠堆一堆低分规则冲过阈值：

score = clamp(max(weight_i) + min(20, 4 * log2(1 + hits)), 0, 100)

阈值定在两处：60 进人工复核队列，80 直接隔离。这两个数是在 12 万条历史样本上（口径：仅静态扫描，不含沙箱）按「误报 ≤ 0.2%」反推出来的，换个样本集就得重算。

判定的可解释性怎么落到字段上

每条判定结果里必须带四样东西：命中规则名、命中位置（偏移或容器内路径）、分数构成、以及流水线版本号。前两个给人看，后两个用来复现。

少了版本号，同一份文件隔一周扫出两个结论就没法解释，因为规则集或者解包器在这期间变过。这条要求后来被写进结果格式的强制字段，比任何评审都管用。
